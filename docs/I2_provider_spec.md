| | |
| :-- | :-- |
| Файл | `app/drafts/provider.py` |

| Оценка | 260 LOC, 14 тестов |
| Зависит от | I1 (`library.py`), I5 (`guardrails.py` ✅), D1 (`base.py` ✅), B1 (config) |
| Блокирует | обработчик `JobType.DRAFT` (H1 фаза 2), вкладка E4 |
| Пункт спеки | §12 (генератор черновиков), §10.3 |

## Граница модуля — прочитать первым

I2 **производит** черновик и отдаёт его `DraftGuard` (I5). I2 **не**
проверяет числа, источники, пробелы и **не** пишет в БД — это уже делает
I5, код прочитан:
- `DraftGuard.verify(candidate, library_text)` проверяет числа против
  библиотеки, источники, пробелы, длину;
- `DraftGuard.store(candidate, verdict)` — единственный путь записи.

Значит I2 — это: **взять вопрос клиента → собрать промпт с библиотекой →
вызвать LLM → распарсить ответ в `DraftCandidate` → отдать guard'у.**
Проверку и запись I2 не трогает. Это резко сужает модуль: вся логика
«безопасности числа» уже в I5, дублировать её — ошибка.

Поток целиком:
```
trigger(I3) детектировал вопрос
      → I2.generate(вопрос) собирает DraftCandidate
      → guard.verify(candidate, library_text) → Verdict
      → guard.store(candidate, verdict) → draft_id | None
      → (позже) I4 переводит черновик
```
I2 отвечает только за первую стрелку.

## Интерфейс

```python
@dataclass(frozen=True, slots=True)
class DraftProviderConfig:
    max_words: int = 120                 # синхронно с GuardConfig.max_words
    gap_marker: str = "нет данных"       # синхронно с GuardConfig.gap_marker
    temperature: float = 0.0
    cache_library: bool = True           # prompt caching префикса

@dataclass(frozen=True, slots=True)
class DraftRequest:
    session_id: str
    trigger_segment_id: str
    question_text: str                   # реплика клиента (raw_text)
    target_language: str                 # язык встречи (куда переводить потом)
    library_section_id: str              # активный раздел (I1)

class DraftProvider:
    def __init__(self, provider: TranslationProvider, library: "Library",
                 config: DraftProviderConfig | None = None) -> None: ...

    async def generate(self, req: DraftRequest, *, fence: Fence
                       ) -> DraftCandidate | None: ...
        # None = черновик не сгенерирован (пустой вопрос, провайдер недоступен)

    def snapshot(self) -> dict: ...
```

Возвращает `DraftCandidate` (из I5) — **не** пишет его. Вызывающий
(обработчик DRAFT) прогоняет через `guard.verify` + `guard.store`.

## Поведение

1. **Черновик на русском.** Спека §12: генерация всегда на `ru`, перевод
   на язык встречи — отдельный шаг (I4). `DraftCandidate.draft_ru` — по
   определению русский. `target_language` кладётся в кандидат для
   последующего I4, но сам текст черновика от языка встречи не зависит.

2. **Библиотека — весь контекст, без RAG.** Спека §12: библиотека фактов
   (≤30k токенов) вставляется в промпт **целиком** как префикс, без
   выборки. I2 берёт полный текст раздела через `library.get_text(
   section_id)` (I1) и кладёт в системный промпт. Никакого поиска,
   ранжирования, эмбеддингов — весь раздел, дословно.

3. **Prompt caching префикса.** Библиотека — стабильный префикс, вопрос —
   переменная часть. При `cache_library=True` библиотечный блок
   помечается для кэширования провайдером (Claude/Gemini prompt caching),
   чтобы не платить за токены библиотеки на каждый вопрос. Механизм
   пометки зависит от провайдера — см. «Провайдер-специфика».

4. **Промпт требует структурированный ответ.** LLM обязан вернуть:
   - текст ответа (russ, ≤ max_words);
   - список источников (какие факты из библиотеки использованы);
   - явную пометку пробела, если ответа в библиотеке нет.
   Формат — JSON (как post_clean D4) либо строгая разметка. Промпт
   инструктирует: «если данных в справке нет — верни `gap_marker` в
   ответе и пустой список источников, НЕ выдумывай числа».

5. **Разбор ответа в `DraftCandidate`.** Поля:
   - `draft_ru` = текст ответа;
   - `sources` = список источников из ответа (кортеж строк);
   - `has_gaps_claimed` = `True`, если модель вернула пробел ИЛИ
     `gap_marker` присутствует в тексте;
   - `gap_note` = пояснение пробела, если есть;
   - `session_id`, `trigger_segment_id`, `target_language` — из запроса.

6. **`has_gaps` форсируется по факту, не только по слову модели.** Если в
   тексте есть `gap_marker` («нет данных»), `has_gaps_claimed=True`
   независимо от того, что модель заявила в структуре. Модель может
   написать «нет данных» в тексте, но забыть выставить флаг — I2
   выравнивает. Это дешёвая страховка перед строгой проверкой I5.

7. **I2 не смягчает и не правит числа.** Соблазн «убрать выдуманное число
   перед отдачей guard'у» — запрещён. I2 отдаёт ровно то, что вернула
   модель; отбраковка чисел вне библиотеки — работа I5 (`strict_numbers`).
   Если I2 начнёт чистить числа сам, строгая проверка потеряет смысл, а
   дефект уедет в необнаруживаемую зону.

8. **Приватность — через провайдер.** `generate` получает `fence`
   параметром (от обработчика DRAFT), передаёт в `provider.translate`/
   вызов. I2 сам `require()` **не** вызывает — тот же урок, что base.py и
   I4. Черновик — это `DRAFT_GENERATION` + `TEXT_TO_CLOUD` capability;
   fence проверяется провайдером после вызова.

9. **Провайдер недоступен → `None`.** Если провайдер бросил
   `ProviderError` — пробросить (обработчик DRAFT решит ретрай через
   queue). Если вопрос пустой или библиотека пуста → `None` без вызова
   LLM: генерировать нечего.

10. **Ретраев внутри нет.** Как все провайдер-модули: повтор — queue.

11. **`snapshot()`** для E5: сгенерировано, отклонено (по возврату guard,
    если I2 его наблюдает — опц.), пустых вопросов, обращений с кэш-хитом
    библиотеки.

## Провайдер-специфика prompt caching

Кэширование префикса реализуется по-разному:
- **Claude:** блок с `cache_control: {type: "ephemeral"}` на конце
  библиотечного контента в `system` или первом user-блоке;
- **Gemini:** `cachedContent` API или неявное кэширование префикса.

I2 не хардкодит один способ. Библиотечный блок передаётся провайдеру с
флагом «кэшируемо», а как именно пометить — знает провайдер (D2/D3). Если
в D2/D3 нет метода пометки кэша — это **gap**: зафиксировать, что prompt
caching требует расширения провайдера, и в MVP работать без кэша
(`cache_library=False` как временный дефолт), не выдумывая механизм в I2.

## Запрещено

- Проверять числа, источники, пробелы — это I5 (`verify`). I2 только
  собирает кандидата.
- Писать в `draft_answers` — только `guard.store` (I5).
- Править или удалять числа из ответа модели перед отдачей guard'у.
- Делать RAG / выборку по библиотеке — весь раздел целиком (§12).
- Генерировать черновик не на русском.
- Вызывать `privacy.require()` внутри — fence приходит параметром.
- Ретраить внутри модуля.
- Выдумывать механизм prompt caching, если провайдер его не
  поддерживает — зафиксировать gap, работать без кэша.
- Логировать `question_text`, `draft_ru`, содержимое библиотеки на
  уровне INFO+ (там коммерческие условия).
- Доставлять черновик куда-либо — доставка только по действию
  пользователя (§13, это G3/E4).

## Критерии приёмки

- [ ] `generate` на вопрос с фактом в библиотеке → `DraftCandidate` с
      непустыми `sources`, `has_gaps_claimed=False`
- [ ] `generate` на вопрос БЕЗ факта в библиотеке → `draft_ru` содержит
      `gap_marker`, `has_gaps_claimed=True`, `sources=()`
- [ ] Библиотека вставляется в промпт **целиком** (проверяется
      перехватом запроса: весь текст раздела в промпте)
- [ ] `draft_ru` на русском независимо от `target_language`
- [ ] `gap_marker` в тексте → `has_gaps_claimed=True`, даже если модель
      не выставила флаг в структуре
- [ ] Число, которого нет в библиотеке, **не удаляется** I2 — уходит в
      кандидат как есть (проверяется: guard потом его отбракует)
- [ ] Пустой вопрос → `None`, LLM не вызывался
- [ ] Пустая библиотека → `None`, LLM не вызывался
- [ ] `ProviderRateLimited` из провайдера пробрасывается наружу
- [ ] `fence` передаётся в вызов провайдера; `require()` внутри не
      вызывается (проверяется подменённым privacy с падающим `require`)
- [ ] Модуль не пишет в БД (подменённый Database с падающими write)
- [ ] `question_text` и `draft_ru` не в логах INFO+
- [ ] `cache_library=False` при провайдере без кэша → работает без
      исключения, gap зафиксирован в snapshot
- [ ] Кандидат содержит `trigger_segment_id` и `target_language` из
      запроса (для I4 и привязки)

## Подсказки

Сборка (концептуально, сверить с фактическим API провайдера):
```python
library_text = await self._library.get_text(req.library_section_id)
if not library_text or not req.question_text.strip():
    return None
system = self._build_system(library_text)      # библиотека = префикс
user = self._build_user(req.question_text)      # вопрос = переменная часть
result = await self._provider.generate_draft(   # или .translate с DRAFT-режимом
    system=system, user=user, fence=fence,
    cache_prefix=self._config.cache_library,
)
candidate = self._parse(result, req)            # -> DraftCandidate
return candidate
```

Ловушки:
- `max_words` и `gap_marker` в I2 и в `GuardConfig` — **два места одной
  константы**. Рассинхрон = черновик генерится под один лимит,
  бракуется под другой. Брать оба из одного конфига (B1), не хардкодить
  в I2;
- `DraftProvider` в контракте назван так же, как `TranslationProvider` —
  не путать: I2 **использует** провайдера перевода (или его draft-режим),
  а не является им. Если базовый провайдер не имеет draft-метода — это
  расширение D1/D2/D3, зафиксировать как зависимость;
- источники (`sources`) модель склонна выдумывать — если в библиотеке
  разделы не имеют явных меток, модель вернёт правдоподобные, но ложные
  имена. Промпт должен требовать цитировать **точные** заголовки
  разделов из префикса, а разбор — сверять их с реально переданными;
- пустой `sources` при непустом ответе без пробела → I5 забракует
  («из воздуха»). Это правильно, но I2 должен понимать: промпт обязан
  требовать источники, иначе каждый второй черновик отлетит на verify;
- prompt caching даёт экономию только если префикс **байт-в-байт**
  стабилен между вызовами — любая правка библиотеки инвалидирует кэш
  (это в I1: нормализация один раз при записи, не при чтении).

## Открытое решение владельца (блокирует дефолт)

Решение №2 (`INTERFACES.md §10`): строгий `DraftGuard`
(`strict_numbers=True`) по умолчанию. I5 уже имеет `strict_numbers=True`
дефолтом в `GuardConfig`. I2 это **не меняет** — он не проверяет числа.
Но промпт I2 должен быть согласован со строгим режимом: если строгий,
промпт обязан жёстко требовать «только числа из справки, иначе
`gap_marker`» — иначе каждый черновик с числом вне библиотеки будет
отбракован, и вкладка черновиков окажется пустой. Подтвердить у
владельца, что строгий режим — дефолт, и настроить промпт под него.

## Для реализатора: почему это Middle+, а не Senior

Сложность I2 не в объёме, а в **дисциплине границы**: соблазн проверить
числа/источники самому (это I5), почистить ответ модели (запрещено),
захватить fence (это вызывающий). Модуль прост, если границу держать, и
опасен, если её размыть. Плюс prompt caching — единственное
провайдер-специфичное место, требующее аккуратности с D2/D3. Сильный
middle справится по этой спеке; рядовой размоет границу с I5.
