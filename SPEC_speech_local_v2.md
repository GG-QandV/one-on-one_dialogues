# СПЕЦИФИКАЦИЯ: speech-local v2.0

Документ предназначен для агентов-исполнителей, ревьюеров и владельца проекта.
Используется совместно с `ROADMAP_speech_local_v2.md`.
Версия 2.0 отменяет и заменяет v1.0.

## 0. Что изменилось относительно v1.0

| Изменение | Причина |
| :-- | :-- |
| Приоритет направления инвертирован: исходящий поток 70%, входящий 30% | Реальное соотношение трафика |
| Двусторонний режим перенесён из тира 2 в MVP | Следствие соотношения 30/70 |
| Введены профили конфиденциальности: открытый / конфиденциальный | Часть диалогов допускает облачную обработку аудио |
| Введены два трека обработки: быстрый (черновик) и точный (проверенный) | Потолок задержки 3 с при требовании точности |
| Сегментация по паузе вместо фиксированной длины | Естественные границы реплик |
| Добавлен генератор черновиков ответов на базе библиотеки фактов | Требование владельца |
| Доставка текста — буфер обмена; TTS исключён | Пользователь читает текст сам |
| Порог RAM поднят до 2.1 ГБ | Уточнены параметры машины |
| Режим whisper зафиксирован: файл-на-сегмент, JSON-вывод | Требуется avg_logprob и таймкоды |
| VPS-развёртывание перенесено в тир 2 | Требует иного механизма захвата аудио |

## 1. Назначение

Локальный сервис live-транскрибации и перевода речи во время звонков (Zoom, Google Meet, MS Teams) с генерацией черновиков ответов на основе библиотеки фактов о продукте.

### Основной контур

```
[Микрофон: моя речь RU]  ----+
                             |
[Звук встречи: EN/ES/PL] ----+--> VAD -> сегменты
                                        |
                     +------------------+------------------+
                     |                                     |
              БЫСТРЫЙ ТРЕК                          ТОЧНЫЙ ТРЕК
       (частичный текст, черновик)         (финальный сегмент, проверенный)
                     |                                     |
                     |                          локальный whisper.cpp
                     |                                     |
                     |                          SQLite: raw_text (неизменяем)
                     |                                     |
                     |                          перевод live_literal / live_safe
                     |                                     |
                     +------------------+------------------+
                                        |
                              Web UI: 3 вкладки
                     [Перевод] [Черновики ответов] [Диагностика]
                                        |
                              Буфер обмена / экспорт
```

### Границы ответственности

| Компонент | Где | Профиль «открытый» | Профиль «конфиденциальный» |
| :-- | :-- | :-- | :-- |
| PipeWire, захват, нормализация | Локально | Да | Да |
| VAD, сегментация | Локально | Да | Да |
| whisper.cpp (точный трек) | Локально | **Всегда** | **Всегда** |
| SQLite, `raw_text` | Локально | Да | Да |
| Быстрый трек (аудио в облако) | Облако | Да | **Отключён** |
| Перевод текста | Облако | Да | Да |
| Генератор черновиков | Облако | Да | Да |
| Web UI, экспорт | Локально | Да | Да |

**Инвариант:** локальный whisper работает всегда, в обоих профилях. Он — единственный источник неизменяемого `raw_text`. Облачные компоненты никогда не пишут в это поле.

## 2. Профили конфиденциальности

| Профиль | Что уходит в облако | Задержка перевода |
| :-- | :-- | --: |
| **Открытый** | Аудио (быстрый трек) + текст сегментов | 0.8–1.5 с черновик, 2.5–3.5 с проверенный |
| **Конфиденциальный** | Только текст сегментов | 2.5–3.5 с |

### Правила переключения

1. Профиль задаётся до старта сессии и **переключается по ходу разговора** одним действием, без подтверждения (скорость важнее).
2. Переход в конфиденциальный: принудительное закрытие облачной аудио-сессии (WebSocket), сброс буферов «в полёте», отказ от результатов незавершённых облачных запросов на аудио.
3. Возврат в открытый: пересоздание сессии, разрыв обслуживания 0.5–1.5 с — допустим.
4. Каждый сегмент помечается полем `privacy_profile` — под каким профилем он обработан. Поле неизменяемо.
5. UI показывает текущий профиль крупным постоянным индикатором. Двусмысленность недопустима.
6. Допустимый сценарий использования: сессия разбивается на общую и конфиденциальную части — поддерживается тем же механизмом.

## 3. Два трека обработки

| | Быстрый трек | Точный трек |
| :-- | :-- | :-- |
| Назначение | Понять смысл немедленно | Зафиксировать факты корректно |
| Вход | Частичные результаты STT / поток аудио | Финальный сегмент по паузе |
| Движок | Облачный realtime либо частичный вывод локального whisper | Локальный whisper.cpp |
| Перевод | Быстрая модель без гарантии сохранения фактов | `live_literal` / `live_safe` |
| Задержка | 0.8–1.5 с | 2.5–3.5 с |
| Отображение | Серым, метка «черновик» | Заменяет черновик, метка «проверено» |
| Пишется в `raw_text` | **Нет** | **Да** |
| Идёт в экспорт | Нет | Да |
| Доступен в конфиденциальном профиле | Только локальный вариант | Да |

**Правило замещения:** черновик всегда замещается проверенной версией в той же карточке. Черновик никогда не остаётся конечным результатом в БД и экспорте.

## 4. Направления и приоритеты

| Поток | Источник | Направление | Доля трафика | Приоритет |
| :-- | :-- | :-- | --: | :-- |
| `mic_audio` | Микрофон пользователя | RU → EN/ES | **70%** | **Основной** |
| `meeting_audio` | Звук встречи | EN/ES/PL → RU | 30% | Вторичный |

Двусторонний режим входит в MVP. Смешивание потоков запрещено; для каждого хранятся роль, исходный и целевой язык, узел PipeWire, статус.

### Языки

| Язык | Распознавание | Цель перевода | Тир |
| :-- | :-- | :-- | :-- |
| EN | Да | Да | MVP |
| ES | Да | Да | MVP |
| RU | Да | Да | MVP |
| UA | Да | Через текстовый LLM | Тир 2 |
| PL | Да | Через текстовый LLM | Тир 2 |

Причина ограничения по UA/PL: облачные realtime-модели перевода их в выходных языках не поддерживают (раздел 10).

### Определение языка

1. Ручная установка `source_language` на поток — приоритетный режим.
2. Автораспознавание whisper — результат в `segments.detected_language`.
3. При конфликте: для перевода используется заданный язык, расхождение фиксируется в логе и показывается индикатором. Переключение — только вручную.

## 5. Сегментация и бюджет задержки

### Правила VAD

| Параметр | Значение | Настраиваемо |
| :-- | :-- | :-- |
| Порог паузы для закрытия сегмента | **800 мс** (диапазон 800–1200) | Да |
| Минимальная длина сегмента | 0.8 с | Да |
| Принудительная резка | 15 с | Да |
| Частота частичных результатов | 500–800 мс | Да |
| Аудио в RAM | Не более 30–60 с необработанного | Да |

**Обоснование порога:** пауза входит в задержку целиком. Порог 1.5–2.0 с даёт итоговую задержку 3.3–4.5 с и не укладывается в потолок 3 с.

### Бюджет задержки точного трека

| Этап | мс |
| :-- | --: |
| Пауза до закрытия сегмента | 800 |
| Нарезка и запись файла | 50–100 |
| Локальный whisper base, сегмент 3–5 с | 500–900 |
| Формирование запроса и сеть | 100–250 |
| Перевод текстовой моделью (быстрый тир) | 600–1100 |
| Рендер SSE | ~50 |
| **Итого (медиана по модели)** | **~2820** |

**Потолок: 3000 мс, запас ~180 мс.** Обоснование дефолта 800: при 900 мс запас падает до 36 мс, при 1000 мс медиана уходит за потолок (3061 мс). Проверяется тестом `tests/test_latency_budget.py`.

Плата за нижнюю границу: пауза внутри фразы длиннее 800 мс разрежет реплику на два сегмента. Порог настраиваемый — при жалобах на дробление поднимается, но тогда пересматривается модель перевода в сторону более быстрой.

| Параметр | Прод (локально) | Демо (VPS, тир 2) |
| :-- | :-- | :-- |

Запрещено в MVP: Ollama, локальная LLM, pyannote, NLLB, PostgreSQL, Qdrant, тяжёлый Python-ML runtime, TTS.

## 7. Стек

| Компонент | Технология |
| :-- | :-- |
| STT (локальный) | whisper.cpp, `ggml-base.bin` multilingual. **НЕ `base.en`** |
| Режим вызова whisper | **Файл-на-сегмент**, `whisper-cli` с JSON-выводом (нужны таймкоды и `avg_logprob`) |
| Fallback-модель | `ggml-tiny.bin` при перегрузке |
| VAD | Энергетический детектор на нормализованном потоке, пороги из конфига |
| Аудиозахват | PipeWire, два независимых узла |
| Нормализация | FFmpeg → mono / 16 000 Hz / PCM s16le |
| Хранилище | SQLite (WAL, foreign_keys, busy_timeout, единый writer queue) |
| Backend | Python 3.11+ asyncio, FastAPI или aiohttp |
| Web UI | HTML + CSS + vanilla JS, SSE или WebSocket |
| Облачные модели | Через интерфейсы `TranslationProvider`, `RealtimeProvider`, `DraftProvider` |
| Сервисы | systemd user units: gateway + watchdog |

**Один экземпляр whisper.cpp.** Два потока обслуживаются последовательно через общую очередь задач. Параллельный запуск второй модели запрещён.

## 8. Схема данных (SQLite)

```sql
sessions:
  id, started_at, ended_at, meeting_title, status,
  default_privacy_profile,        -- open | confidential
  library_context_id,             -- выбранный раздел библиотеки фактов
  translation_provider, draft_provider, mode

audio_streams:
  id, session_id, role,           -- meeting | microphone
  source_language, target_language, pipewire_node, enabled

segments:
  id, session_id, stream_id, t_start_ms, t_end_ms,
  local_audio_path,               -- NULL после удаления по retention
  privacy_profile,                -- НЕИЗМЕНЯЕМ: профиль на момент обработки
  track,                          -- fast | accurate
  stt_model, detected_language,
  raw_text,                       -- НЕИЗМЕНЯЕМ, только из локального whisper
  stt_confidence,                 -- усреднённый avg_logprob по токенам сегмента
  translation_status, translation_raw, translation_clean,
  edit_log_json, superseded_by_segment_id,
  created_at

draft_answers:
  id, session_id, trigger_segment_id,
  draft_ru,                       -- черновик на русском (генерация)
  draft_translated,               -- перевод через live_literal
  target_language,
  sources_json,                   -- разделы библиотеки, откуда взяты факты
  status,                         -- generated | ignored | copied
  created_at

library_contexts:
  id, name, domain, content_text, token_estimate, updated_at

jobs:
  id, type,                       -- stt | translate | draft | export
  segment_id, status, attempts, error_code, created_at, updated_at
```

### Инварианты целостности

1. `raw_text` неизменяем после записи; заполняется только локальным whisper.
2. `privacy_profile` неизменяем; отражает фактические условия обработки.
3. Результаты быстрого трека никогда не пишутся в `raw_text` и не попадают в экспорт.
4. `translation_raw`, `translation_clean`, `edit_log_json` — раздельные поля; редактор не перезаписывает оригинал.
5. `draft_answers` никогда не смешивается с `translation_*`.
6. Аудиофайлы — только в папке сессии.
7. Недоступность облака не останавливает локальный STT и запись.
8. Все записи в SQLite — через единый writer queue.

### Retention аудио

Настраиваемо, значение по умолчанию — **удаление аудиофайла сразу после успешного STT**. Иные значения (24 ч, 7 дней, хранить) — только при явной установке.

## 9. Облачные провайдеры: фактические возможности

Данные проверены по источникам на июль 2026. Перед фиксацией выбора провести живые тесты — цены и составы моделей меняются.

| Провайдер | Модель | Возможность | Цена | Ограничение |
| :-- | :-- | :-- | :-- | :-- |
| OpenAI | `gpt-realtime-translate` | Непрерывный перевод аудио → аудио + транскрипт, без сегментации | ~$0.034/мин | **Не поддерживает кастомные промпты.** 70+ входных, 13 выходных языков: EN, ES, PT, FR, DE, IT, RU, ZH, JA, KO, HI, ID, VI. **UA и PL отсутствуют** |
| OpenAI | `gpt-realtime-whisper` | Потоковый STT | ~$0.017/мин | — |
| Google | `gemini-3.5-live-translate-preview` | Audio-to-audio перевод, 70+ языков | ~$0.037/мин на поток | Preview |
| Google | Gemini Flash / Flash-Lite | Текстовый перевод, генерация черновиков, приём аудио на обычных эндпоинтах | По токенам | — |
| Anthropic | Claude (Messages API) | **Только текст.** Аудио как тип контента отсутствует | По токенам | Не может использоваться в быстром треке |

### Следствия для архитектуры

1. `gpt-realtime-translate` применим **только** в быстром треке входящего потока и **только** в открытом профиле. Для исходящего потока неприменим: отсутствие кастомных промптов не позволяет гарантировать сохранение чисел, сумм и имён.
2. Claude применим как текстовый переводчик и генератор черновиков, но не как приёмник аудио.
3. UA и PL как цели перевода обслуживаются только текстовыми моделями.

## 10. Интерфейсы провайдеров

### 10.1 TranslationProvider (текст)

```
translate(segment, source_language, target_language, mode, context) -> TranslationResult
```

```json
{
  "translation_raw": "string",
  "translation_clean": "string or null",
  "changes": [{"type": "filler_removed | punctuation | other",
               "original": "string", "replacement": "string"}],
  "provider_request_id": "string or null"
}
```

### 10.2 RealtimeProvider (аудио, только открытый профиль)

```
open_session(source_language, target_language) -> session_handle
push_audio(session_handle, pcm_chunk)
on_transcript_delta(callback)
close_session(session_handle)
```

Обязательно: принудительное закрытие сессии при переходе в конфиденциальный профиль.

### 10.3 DraftProvider (черновики ответов)

```
generate_draft(question_segment, library_context, dialog_history) -> DraftResult
```

```json
{
  "draft_ru": "string",
  "sources": ["раздел библиотеки", "..."],
  "has_gaps": true,
  "gap_note": "string or null"
}
```

### Контекст перевода (динамическое окно)

| Длина сегмента (знаков) | Окно предыдущих сегментов |
| :-- | :-- |
| < 100 | 4 |
| 100–200 | 3 |
| > 200 | 2 |

Пороги настраиваемы. Перевод потоковый: контекст прикладывается к каждому запросу и не задерживает обработку.

### Ретраи

Exponential backoff, максимум 3 попытки, только идемпотентные запросы. При исчерпании — `job → failed`, ручной повтор из истории сессий.

## 11. Режимы перевода

### 11.1 `live_literal` — точный live

Обязателен для исходящего потока (ваши цифры и обязательства) и для перевода черновиков ответов.

```
Переведи текст с {source_language} на {target_language}.
Не добавляй и не удаляй факты.
Сохрани числа, суммы, валюты, даты, имена, названия компаний,
артикулы, номера, ссылки и единицы измерения без изменений.
Не объясняй перевод. Верни только перевод.
```

### 11.2 `live_safe` — очищенный live

```
Переведи текст с {source_language} на {target_language}.
Удаляй только отдельные очевидные междометия и слова-паразиты:
«ээ», «эээ», «эм», «эмм», «мм», «ммм», «uh», «um», «er».
Не удаляй слова, если они могут менять смысл.
Сохраняй все факты, числа, имена, даты и названия.
Верни только перевод.
```

### 11.3 `post_clean` — чистовая после встречи

```
Отредактируй стенограмму без изменения смысла.
Удали очевидные слова-паразиты, ложные старты и бессмысленные повторы.
Восстанови пунктуацию и абзацы.
Не меняй числа, даты, валюты, имена, названия, ссылки,
обязательства, решения и степень уверенности говорящего.
Верни JSON: {"clean_text": "...", "changes": [...]}
```

`post_clean` никогда не применяется к live-переговорам автоматически.

## 12. Генератор черновиков ответов

### Механизм

| Параметр | Значение |
| :-- | :-- |
| Размер библиотеки | **До 30 000 токенов** |
| Способ подачи | Полная вставка в контекст запроса + prompt caching (кэширование префикса запроса — повторный контекст тарифицируется по сниженной ставке) |
| RAG | **Не используется.** При превышении 150 тыс. токенов — тир 2 |
| Переключение | Одна база, раздел выбирается перед встречей (`sessions.library_context_id`) |
| Триггер | **Автоматически на каждый вопрос клиента** во входящем потоке |
| Язык генерации | **Русский**, затем перевод через `live_literal` в EN/ES |
| Отображение | Отдельная вкладка UI |

### Обязательные ограничители

| Правило | Реализация |
| :-- | :-- |
| Черновик никогда не отправляется автоматически | Нет пути «сгенерировал → доставил» без действия пользователя |
| Визуальное отличие от перевода | Отдельная вкладка, иной цвет, постоянная метка «черновик, не проверен» |
| Только факты из библиотеки | Промпт: при отсутствии факта — вернуть «нет данных», не додумывать; `has_gaps: true` |
| Прослеживаемость | Каждый черновик хранит `sources_json` — разделы библиотеки |
| Изоляция данных | Поля `draft_*` никогда не пишутся в `translation_*` и не идут в стенограмму |

### Промпт генератора

```
Ты готовишь черновик ответа на вопрос клиента.
Используй ТОЛЬКО факты из предоставленной библиотеки.
Если факта в библиотеке нет — напиши «нет данных по этому пункту»
и укажи это в поле has_gaps. Не придумывай цены, сроки и условия.
Для каждого использованного факта укажи раздел библиотеки.
Ответ на русском языке, деловой тон, не более 120 слов.
Верни строгий JSON.
```

## 13. Доставка текста

| Механизм | Тир | Покрытие | LOC |
| :-- | :-- | :-- | --: |
| **Буфер обмена по горячей клавише** | **MVP** | 100%, включая десктопный Zoom | 80 |

**Пояснение по Zoom:** десктопный клиент — нативное приложение без DOM, программная вставка в чат невозможна. Веб-клиент Zoom существует и позволяет вставку через расширение, но доступность входа через браузер определяет хост встречи и может быть отключена. Поэтому единственный механизм со 100% покрытием — буфер обмена.

**TTS и озвучка перевода исключены из проекта** — пользователь читает текст сам.

## 15. Память и деградация

| Слой | МБ |
| :-- | --: |
| whisper.cpp base + KV + буферы | 550–700 |
| Python gateway + UI | 180–260 |
| Захват + FFmpeg | 120–180 |
| SQLite, очередь, буферы | 60–120 |
| HTTP/WebSocket клиенты провайдеров | 40–80 |
| Резерв на пики и GC | 400–500 |
| **Итого** | **1350–1840** |

systemd: `MemoryHigh=1750M`, `MemoryMax=2000M`. Watchdog читает cgroup `memory.current` каждые 2 секунды.

### Каскад деградации

| Триггер | Действие |
| :-- | :-- |
| Задержка точного трека > 3000 мс | Сократить окно контекста; перейти на более лёгкую модель перевода; уменьшить порог паузы |
| Очередь STT растёт | Короче сегменты; отключить частичные результаты; аудио на диск |
| Облако недоступно | Локальный STT продолжается; задачи перевода и черновиков в очередь; UI: «перевод будет восстановлен»; догон после восстановления |
| RAM > 1750 МБ | Отключить кэши; не брать новые задачи; буферы на диск |
| RAM > 1900 МБ | Корректно остановить STT worker; сохранить очередь; режим только записи |
| CPU не успевает | Переход base → tiny; при сохранении отставания — режим записи с постобработкой |

Приоритет: **сохранность данных выше скорости live**.

## 16. Безопасность

| Правило | Реализация |
| :-- | :-- |
| Передача ключа | Только HTTPS POST body |
| Хранение | Только RAM изолированного session worker, TTL 60 минут, кнопка Revoke |
| Запрещено | SQLite, файлы, URL, localStorage, cookies, аналитика, exception traces, access/debug логи |
| LogRedactor | Маскирует паттерны ключей до записи любого лога, включая трейсы исключений |
| Локальный режим | Ключ через systemd EnvironmentFile, права 0600; `.env` не коммитится |
| UI | Ключ после ввода — только маска |
| README | Честное объяснение: ephemeral BYOK означает отсутствие записи на диск и автоудаление по TTL, а не невозможность доступа сервера к ключу |
| Аудио в открытом профиле | README прямо указывает: аудио передаётся провайдеру; в конфиденциальном профиле — не передаётся |

## 17. Надёжность

- Health endpoints: `/health`, `/ready`.
- Graceful shutdown: стоп intake → завершение текущего сегмента → закрытие облачных сессий → сброс SQLite WAL → сохранение состояния очереди.
- При старте: восстановление задач `queued` и `running`; повтор только идемпотентных.
- Обязательные тесты: схема и инварианты, восстановление очереди, валидация режимов промптов, редактирование логов, экспорт SRT/VTT, изоляция профилей, ограничители генератора черновиков.

## 18. PipeWire

- Discovery источников: `wpctl` / `pw-dump` либо pactl-совместимый слой.
- UI: выбор узла для `meeting_audio` и `mic_audio`.
- **Не обещать** автоматический универсальный захват системного звука. README — пошаговая инструкция создания virtual sink/source для Zoom, Meet, Teams.
- Никакой mock-логики: если захват не гарантирован без конкретного узла — диагностика и ручная настройка, ограничение не скрывается.
- При работе через веб-клиент встречи звук идёт через браузер как обычный PipeWire-клиент; дополнительной логики не требуется.

## 21. Критерии приёмки MVP

1. Запуск на Linux Mint Cinnamon без Docker, GPU и тяжёлого Python-ML стека.
2. Раздельный захват выбранного узла PipeWire и микрофона; оба потока активны одновременно.
3. Локальное распознавание тестовых EN, ES, RU, UA, PL фрагментов через `ggml-base.bin`.
4. `raw_text` с таймкодами и `stt_confidence` сохраняется в SQLite; заполняется только локальным whisper.
5. Задержка точного трека не превышает 3000 мс на сегментах 3–5 с (медиана по 50 репликам).
6. Черновик быстрого трека появляется не позже 1500 мс и замещается проверенной версией.
7. Переключение профиля по ходу сессии закрывает облачную аудио-сессию; в конфиденциальном профиле сетевой трафик с аудио отсутствует (проверяется перехватом).
8. `privacy_profile` корректно проставлен у каждого сегмента.
9. В `live_literal` числа, даты, имена, суммы и URL не изменяются (эталонный набор 20 фрагментов).
10. Черновик ответа генерируется автоматически на вопрос клиента, содержит источники из библиотеки, при отсутствии факта возвращает `has_gaps`.
11. Черновик невозможно доставить без явного действия пользователя; копирование в буфер работает горячей клавишей.
12. Недоступность облака не останавливает локальную запись и транскрибацию; очередь догоняется после восстановления.
13. Экспорт TXT, SRT/VTT, JSON содержит только результаты точного трека.
14. При memory pressure очередь пишется на диск; `MemoryMax` не превышается аварийно.
15. Ключ BYOK не сохраняется на диск и не попадает в логи (проверяется grep по логам и БД).
16. Остановка и перезапуск не повреждают сессию; незавершённые задачи восстанавливаются.
