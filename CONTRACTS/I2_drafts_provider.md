# I2 — генератор черновиков ответов

| | |
| :-- | :-- |
| Файл | `app/drafts/provider.py` |
| Уровень | Middle+ |
| Оценка | 260 LOC, 14 тестов |
| Зависит от | I1 (`library.py`), `app/privacy.py` (готов), I5 (`guardrails.py`, готов) |
| Блокирует | I3 (триггер), I4 (перевод черновиков), вкладка «Черновики» (E) |
| Пункт спеки | §12, §10.3, §19 (`[provider.draft]`, `[draft]`) |

## Задача

Сгенерировать черновик ответа на вопрос клиента, опираясь **только** на
выбранный раздел библиотеки фактов. Русский язык генерации, деловой тон,
не более 120 слов (`[provider.draft].max_words`), строгий JSON на выходе.

Функция стоит в самом опасном месте продукта. Черновик выглядит как ответ
менеджера, но собран моделью; выдуманная цена или срок, попавшие в буфер
обмена и в чат встречи, — это не «неудачный перевод», а обязательство
перед клиентом. Отсюда жёсткость §12: только факты из библиотеки, «нет
данных» вместо догадки, прослеживаемость по разделам, никакой автоотправки.

Второй контур защиты — `DraftGuard` (I5, готов), который сверяет числа с
библиотекой и может отклонить черновик. Этот модуль в него не лезет и на
него не полагается: собственные проверки обязательны.

## Интерфейс

```python
@dataclass(frozen=True, slots=True)
class DraftResult:
    draft_ru: str
    sources: tuple[str, ...]
    has_gaps: bool
    gap_note: str | None

class DraftProvider(Protocol):
    name: str
    async def generate(self, question: str, library: LibraryContext,
                       dialog_history: tuple[str, ...], *,
                       fence: Fence) -> DraftResult: ...
    async def close(self) -> None: ...

@dataclass(frozen=True, slots=True)
class DraftConfig:
    model: str = ""                 # из [provider.draft].model
    max_words: int = 120
    timeout_s: float = 20.0
    max_output_tokens: int = 1024
    temperature: float = 0.0
    history_limit: int = 6

class GeminiDraftProvider(DraftProvider): ...   # активный по умолчанию
class ClaudeDraftProvider(DraftProvider): ...   # тот же контракт
```

## Поведение

1. **Промпт — из спеки §12 дословно**, константой модуля. Подстановка
   допустима только для `max_words`. Переформулировка запрещена той же
   логикой, что и в D4: промпт генератора — предмет приёмки.

2. **Порядок сборки запроса фиксирован и неизменен в пределах сессии:**

   ```
   [system]  промпт §12
   [prefix]  библиотека: library.content_text          ← кэшируемая часть
   [tail]    история диалога (последние history_limit реплик)
   [tail]    вопрос клиента
   ```

   Библиотека всегда идёт **до** истории и вопроса. Перестановка ломает
   кэш префикса: у обоих провайдеров кэшируется именно начало запроса, до
   первой изменившейся части.

3. **Кэширование префикса обязательно** (§12: «полная вставка + prompt
   caching»). У Claude — маркер `cache_control` на последнем блоке
   библиотеки в `system`; у Gemini — механизм кэширования контекста,
   актуальное имя API сверить с документацией перед реализацией. Если
   провайдер кэширование не поддерживает — запрос всё равно отправляется,
   но факт отсутствия кэша попадает в `snapshot()`, а не замалчивается.

4. **Протокол приватности.** Требуется `Capability.DRAFT_GENERATION`.
   `fence` приходит **снаружи** (в отличие от D1, где его берёт базовый
   класс), так как вызывающий обработчик захватывает право раньше — на
   этапе решения генерировать. Обязанность модуля: вызвать
   `privacy.validate(fence, Capability.DRAFT_GENERATION)` после ответа и
   **до** возврата результата. Пропуск — блокирующий дефект.

5. **Строгий JSON на выходе:**

   ```json
   {"draft_ru": "…", "sources": ["раздел", "…"],
    "has_gaps": true, "gap_note": "…"}
   ```

   Разбор невалидного JSON, отсутствие `draft_ru`, `draft_ru` не строка →
   `ProviderResponseInvalid`.

6. **Согласование `has_gaps`.** Если в `draft_ru` встречается формула «нет
   данных» (список вариантов — константа модуля), а модель вернула
   `has_gaps: false` — значение принудительно выставляется в `true`.
   Ошибаться безопасно только в эту сторону: лишняя пометка «есть пробелы»
   стоит внимания пользователя, отсутствующая — стоит выдуманного факта.

7. **Прослеживаемость.** `sources` пуст при `has_gaps == false` →
   `ProviderResponseInvalid` с кодом `draft_without_sources`. Черновик без
   указания разделов нарушает §12 и не может быть проверен постфактум.

8. **Лимит длины.** Превышение `max_words` до 150 % — не ошибка,
   фиксируется в `snapshot()`. Свыше 150 % → `ProviderResponseInvalid`:
   модель ушла в пересказ библиотеки. **Обрезка запрещена** — обрезанный
   черновик теряет оговорки и меняет смысл.

9. **`temperature=0`** и один кандидат. Повтор задачи после сбоя обязан
   давать тот же черновик: `JobQueue` считает задачу идемпотентной.

10. **История диалога** — последние `history_limit` реплик, обрезается
    вызывающим кодом или здесь по хвосту. Передаётся как контекст
    разговора, явно помеченный: это не источник фактов, факты только из
    библиотеки.

11. **Модуль ничего не пишет в БД.** Единственный путь записи черновика —
    `DraftGuard.store` (I5). Модуль возвращает `DraftResult` и всё.

12. **Модуль не переводит черновик.** Перевод на язык встречи через
    `live_literal` — задача I4.

## Запрещено

- Писать в `draft_answers` или в любую другую таблицу.
- Переводить черновик, доставлять его, класть в буфер обмена.
- Обрезать `draft_ru` под лимит слов.
- Ретраить внутри модуля.
- Ставить `temperature > 0` «ради живого языка».
- Менять текст библиотеки перед вставкой — любая правка обнуляет кэш
  (см. I1 п. 4).
- Ставить историю диалога или вопрос **до** библиотеки.
- Логировать `question`, `library.content_text`, `dialog_history` или
  ответ на уровне INFO и выше.
- Генерировать черновик, если `privacy.allows(DRAFT_GENERATION)` ложно —
  проверка идёт через `fence`, а не через собственную копию профиля.
- Подмешивать в промпт «общие знания», примеры ответов, шаблоны писем.

## Критерии приёмки

- [ ] Промпт совпадает со спекой §12 после подстановки `max_words`
      (сравнение с фикстурой, скопированной из спеки)
- [ ] Библиотека находится в запросе строго до истории и вопроса
      (проверяется перехватывающим HTTP-клиентом)
- [ ] Два подряд запроса в одной сессии дают идентичный префикс запроса
      побайтово
- [ ] Маркер кэширования выставлен на последнем блоке библиотеки
- [ ] `privacy.validate` вызывается после ответа и до возврата;
      `switch()` посреди вызова → `StaleGenerationError`, результат
      не возвращается
- [ ] Профиль без `DRAFT_GENERATION` → `PrivacyViolation`, сетевого
      вызова не было
- [ ] Валидный JSON → `DraftResult` с непустым `draft_ru`
- [ ] Невалидный JSON → `ProviderResponseInvalid`
- [ ] `draft_ru` содержит «нет данных», `has_gaps: false` → в результате
      `has_gaps is True`
- [ ] Пустой `sources` при `has_gaps: false` → `ProviderResponseInvalid`
- [ ] 200 слов при `max_words=120` → `ProviderResponseInvalid`,
      обрезки нет
- [ ] 140 слов при `max_words=120` → результат возвращён, факт превышения
      виден в `snapshot()`
- [ ] `dialog_history` длиннее `history_limit` обрезается по хвосту
      (остаются последние реплики)
- [ ] Ключ `sk-CANARY` и текст библиотеки не встречаются в исключениях
      и в `repr`
- [ ] Модуль не выполняет операций записи в БД (проверяется подменённым
      `Database` с падающим `write`)

## Подсказки

Промпт §12 (константа, дословно):

```
Ты готовишь черновик ответа на вопрос клиента.
Используй ТОЛЬКО факты из предоставленной библиотеки.
Если факта в библиотеке нет — напиши «нет данных по этому пункту»
и укажи это в поле has_gaps. Не придумывай цены, сроки и условия.
Для каждого использованного факта укажи раздел библиотеки.
Ответ на русском языке, деловой тон, не более {max_words} слов.
Верни строгий JSON.
```

Схема ответа задаётся средствами провайдера: у Gemini —
`responseMimeType` + `responseSchema` (как в D2), у Claude —
предзаполнение ассистента `"{"` (как в D3). Оба пути ведут к одному
`DraftResult`; общий разбор вынести в приватную функцию модуля.

**Проверить перед реализацией:** имена моделей и актуальный способ
кэширования контекста у обоих провайдеров — сверить с документацией
(`https://docs.claude.com/en/api/messages`, документация Google Gemini).
Имена моделей — из конфига.

Ловушки:
- счёт слов для `max_words` — по `draft_ru`, не по всему JSON; дефис
  внутри слова словоразделителем не считается;
- «нет данных» модель пишет вариативно («данных нет», «в библиотеке нет
  информации») — список маркеров держать коротким и проверять по
  нормализованной строке, но не пытаться покрыть все формулировки:
  второй контур (`DraftGuard`) ловит числа независимо;
- при пустой библиотеке (раздел не выбран) запрос не отправляется вообще —
  это `InvariantViolation` вызывающего кода, а не пустой черновик;
- prompt caching у Claude имеет минимальное время жизни записи и требует,
  чтобы префикс совпадал побайтово; лишний перевод строки, добавленный
  «для красоты», сводит экономию к нулю;
- `snapshot()` полезен для E5: доля кэш-попаданий, средняя длина
  черновика, число отказов по длине и по `sources`.
