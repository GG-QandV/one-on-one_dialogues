## Задача

Превратить строки сессии в четыре формата выгрузки. Логики отбора данных
здесь нет вообще: вход всегда — результат
`SupersedeService.export_view(session_id)`, который уже отдаёт **только
точный трек**.

Это главное свойство модуля и причина, по которой он junior-уровня:
любая собственная выборка из БД мгновенно создаёт риск нарушить инвариант
§8.3 (результаты быстрого трека не попадают в экспорт). Функции чистые,
вход — список строк, выход — строка.

| Формат | Содержимое (§14) |
| :-- | :-- |
| TXT | Исходный и переведённый текст, только точный трек |
| SRT / VTT | Субтитры с исходными таймкодами |
| JSON | Полный audit-след: `raw_text`, переводы, `edit_log`, `privacy_profile`, черновики, ошибки |
| DOCX / PDF | Тир 2, в MVP не реализуются |

## Интерфейс

```python
def to_txt(rows: list[sqlite3.Row]) -> str: ...
def to_json(session: dict, rows: list[sqlite3.Row],
            drafts: list[sqlite3.Row]) -> str: ...
def to_srt(rows: list[sqlite3.Row]) -> str: ...
def to_vtt(rows: list[sqlite3.Row]) -> str: ...

def format_timestamp_srt(ms: int) -> str: ...   # 00:00:01,234
def format_timestamp_vtt(ms: int) -> str: ...   # 00:00:01.234
```

## Поведение

1. **Вход не фильтруется и не досортировывается по своему усмотрению.**
   Порядок строк — как пришёл из `export_view` (по `t_start_ms`).
   Дополнительная сортировка допустима только стабильная и по тому же
   ключу.

2. **TXT.** По одному блоку на сегмент: таймкод, роль, языки, `raw_text`,
   перевод. Перевод отсутствует (`NULL`) — строка перевода пропускается,
   блок остаётся: пропущенный перевод не должен превращать стенограмму в
   дыры без оригинала.

3. **JSON — единственный формат с полным следом.** Обязательные поля
   каждого сегмента: `id`, `t_start_ms`, `t_end_ms`, `role`,
   `detected_language`, `raw_text`, `stt_confidence`, `translation_raw`,
   `translation_clean`, `edit_log_json`, `privacy_profile`,
   `translation_status`, `stt_model`. Плюс блок сессии и блок черновиков.
   `edit_log_json` из БД — строка; в выгрузке она **разбирается в
   объект**, а не вкладывается строкой в строку.

4. **JSON пишется с `ensure_ascii=False`** и отступом 2. Кириллица в
   `\uXXXX` формально валидна, но выгрузку читают люди.

5. **SRT.** Нумерация с 1, таймкод `ЧЧ:ММ:СС,ммм --> ЧЧ:ММ:СС,ммм`,
   разделитель — пустая строка, перевод строки `\r\n` (требование
   формата, многие плееры на `\n` спотыкаются). Текст субтитра —
   **перевод**, при его отсутствии `raw_text`.

6. **VTT.** Первая строка ровно `WEBVTT`, затем пустая строка. Таймкод с
   точкой вместо запятой. Нумерация блоков необязательна и не пишется.

7. **Нулевая и отрицательная длительность.** Сегмент с
   `t_end_ms <= t_start_ms` в субтитрах ломает плеер: длительность
   принудительно поднимается до 1000 мс. В TXT и JSON значения остаются
   как в БД — это audit-след, править его нельзя.

8. **Перекрытие соседних субтитров** (конец предыдущего позже начала
   следующего) допускается и не правится: два потока говорят
   одновременно, и это факт записи. Плееры перекрытие переживают.

9. **Экранирование.** В TXT — ничего. В SRT/VTT — вырезать только
   управляющие символы (`\x00`–`\x08`, `\x0b`, `\x0c`, `\x0e`–`\x1f`).
   Теги `<i>`, `<b>` не вставляются: в тексте переговоров угловые скобки
   встречаются и должны остаться как есть.

10. **Пустой список строк — валидный вход.** TXT → пустая строка,
    JSON → корректный объект с пустым массивом, VTT → `WEBVTT\n\n`,
    SRT → пустая строка. Исключений нет.

11. **Функции чистые.** Ни БД, ни файлов, ни сети: запись файла и выбор
    имени — задача вызывающего (E7, история сессий).

## Запрещено

- Самостоятельно ходить в БД и делать собственные `SELECT`.
- Принимать на вход строки быстрого трека и вообще что-либо, кроме
  результата `export_view` (контракт фиксирует источник; тест это
  проверяет).
- Править `raw_text`: капитализация, пунктуация, склейка соседних
  сегментов запрещены — поле неизменяемо (§8.1) и является источником
  аудита.
- Подставлять `translation_clean` вместо `translation_raw` в TXT/JSON:
  поля раздельные (§8.4), в выгрузке присутствуют оба.
- Включать в экспорт черновики где-либо, кроме отдельного блока JSON:
  `draft_*` не смешивается с `translation_*` (§8.5).
- Реализовывать DOCX и PDF (тир 2).
- Писать файлы на диск.

## Критерии приёмки

- [ ] `format_timestamp_srt(3661234)` → `01:01:01,234`
- [ ] `format_timestamp_vtt(3661234)` → `01:01:01.234`
- [ ] `format_timestamp_srt(0)` → `00:00:00,000`
- [ ] TXT: сегмент без перевода сохраняет оригинал и таймкод
- [ ] TXT содержит и оригинал, и перевод для переведённого сегмента
- [ ] JSON валиден, `ensure_ascii=False`, кириллица читаема
- [ ] JSON: `edit_log_json` присутствует как объект, а не как строка
- [ ] JSON содержит `privacy_profile` каждого сегмента
- [ ] JSON: черновики в отдельном блоке, полей `translation_*` в нём нет
- [ ] SRT: нумерация с 1, разделители `\r\n`, пустая строка между блоками
- [ ] VTT начинается с `WEBVTT` и пустой строки
- [ ] Сегмент с `t_end_ms == t_start_ms` в SRT/VTT получает длительность
      1000 мс; в JSON значения не изменены
- [ ] Перекрывающиеся сегменты выгружаются как есть
- [ ] Управляющие символы вырезаны из SRT/VTT, угловые скобки сохранены
- [ ] Пустой вход даёт корректный результат во всех четырёх форматах
- [ ] Ни один модуль пакета не импортирует `sqlite3` для запросов и не
      открывает файлов (проверяется грепом и подменённым `open`)
- [ ] Интеграционно: строка быстрого трека, добавленная в БД, не
      появляется ни в одном формате (данные берутся через `export_view`)

## Подсказки

Таймкод:

```python
def format_timestamp_srt(ms: int) -> str:
    ms = max(0, ms)
    h, ms = divmod(ms, 3_600_000)
    m, ms = divmod(ms, 60_000)
    s, ms = divmod(ms, 1000)
    return f"{h:02d}:{m:02d}:{s:02d},{ms:03d}"
```

Структура JSON верхнего уровня:

```json
{
  "session": {"id": "...", "started_at": "...", "ended_at": "...",
              "meeting_title": "...", "default_privacy_profile": "open",
              "translation_provider": "gemini", "mode": "live_literal"},
  "segments": [ ... ],
  "drafts": [ ... ],
  "exported_at": "2026-07-25T10:00:00Z"
}
```

Ловушки:
- `sqlite3.Row` ведёт себя как словарь, но не является им: `dict(row)`
  перед сериализацией обязателен, иначе `json.dumps` падает;
- отсутствующий столбец в `Row` даёт `IndexError`, а не `None` — читать
  через `row.keys()` или обёртку с умолчанием, иначе экспорт сломается
  после первой же миграции схемы;
- в SRT перевод строки внутри текста субтитра допустим, а пустая строка
  внутри — нет: она обрывает блок; схлопывать пустые строки в тексте;
- `\r\n` в SRT и `\n` в VTT — не вкусовщина: VTT спецификацией требует
  `\n`, SRT де-факто ждут `\r\n`.
