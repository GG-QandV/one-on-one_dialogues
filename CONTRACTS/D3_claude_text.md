| | |
| :-- | :-- |

| Уровень | Middle |
| Оценка | 210 LOC, 12 тестов |
| Зависит от | D1 (`base.py`), D4 (`prompts.py`) |
| Блокирует | H2 (живые тесты и выбор финальной связки моделей) |

## Задача

Реализовать текстовый перевод через Claude Messages API поверх
`BaseTranslationProvider`. Claude — второй кандидат на роль текстового
переводчика наравне с Gemini (D2); финальный выбор делается по живым
тестам (H2).

Ключевое ограничение спеки §9: Claude принимает **только текст**, аудио
как тип контента отсутствует. В быстром треке он неприменим — никогда.
Его зона: точный трек, все три режима промптов, все направления перевода,
включая UA и PL.

Требование взаимозаменяемости жёсткое: замена `GeminiTextProvider` на
`ClaudeTextProvider` в конфиге не должна требовать ни одной правки в
вызывающем коде и не должна менять результат на эталонном наборе
`tests/fixtures/literal_20.json`.

## Интерфейс

```python
@dataclass(frozen=True, slots=True)
class ClaudeConfig:
    endpoint: str = "https://api.anthropic.com/v1"
    model: str = "claude-haiku-4-5"     # из конфига, в коде не хардкодится
    api_version: str = "2023-06-01"
    timeout_s: float = 15.0
    max_tokens: int = 1024
    temperature: float = 0.0

class ClaudeTextProvider(BaseTranslationProvider):
    name = "claude"
    def __init__(self, config: ClaudeConfig, privacy: PrivacyController,
                 key_provider: Callable[[], str],
                 *, http_client: Any | None = None) -> None: ...
    async def _call(self, req: TranslationRequest, key: str) -> str: ...
    def _parse(self, req: TranslationRequest, raw: str) -> TranslationResult: ...
    async def close(self) -> None: ...
```

## Поведение

1. **Промпты берутся из `prompts.build(mode, req)` (D4)**, не пишутся здесь.
   Тот же запрет, что и в D2: дублирование текстов промптов разводит
   поведение двух провайдеров, и живые тесты H2 начинают сравнивать не
   модели, а копипасту.

2. **Формат запроса.** `POST {endpoint}/messages`. Обязательные заголовки:
   `x-api-key`, `anthropic-version: {api_version}`, `content-type:
   application/json`. Системный промпт — в поле `system` верхнего уровня
   (не первым сообщением роли `user`), пользовательский — в
   `messages[0].content`.

3. **Контекст.** Предыдущие сегменты из `req.context` идут отдельным
   текстовым блоком перед переводимым текстом с явной пометкой «контекст,
   не переводить». Формат блока — из D4, общий с Gemini.

4. **`temperature=0`.** Перевод воспроизводим: одинаковый вход — одинаковый
   выход. Это условие идемпотентности ретраев `JobQueue`.

5. **`POST_CLEAN` требует строгого JSON.** В Messages API нет аналога
   `responseSchema` Gemini. Использовать предзаполнение ответа ассистента:
   последним элементом `messages` передать
   `{"role": "assistant", "content": "{"}` и вернуть открывающую скобку
   обратно в начало ответа перед разбором. Разбор — через
   `prompts.validate_response`, не своим парсером.

6. **Разбор ответа.** Текст лежит в `content[0].text` (первый блок типа
   `text`; блоки других типов игнорировать, а не падать). Условия
   `ProviderResponseInvalid`: пустой `content`, отсутствие текстового
   блока, `stop_reason == "max_tokens"`. В сообщении исключения — код
   причины, но **не** текст запроса и не текст ответа.

7. **`provider_request_id`** — из заголовка ответа `request-id`, при его
   отсутствии из поля `id` тела ответа. Нужен для разбора инцидентов с
   провайдером.

8. **HTTP-клиент инжектируется** параметром `http_client`. По умолчанию
   создаётся `httpx.AsyncClient` с настроенным таймаутом, переиспользуется
   между вызовами, закрывается в `close()`. Инжекция обязательна: тесты
   перехватывают исходящий запрос целиком.

9. **Перегрузка провайдера.** Код 529 приходит при перегрузке и обязан
   классифицироваться как retryable — базовый `_classify` покрывает его
   диапазоном 500–599, отдельной ветки не писать. Заголовок `retry-after`
   при 429 сохранять в атрибут исключения; решение о паузе принимает
   `JobQueue`, не провайдер.

10. **Отказ модели переводить.** Ответ вида «я не могу перевести этот
    текст» приходит с `stop_reason: "end_turn"` и кодом 200. Базовый класс
    ловит только пустую строку. Здесь дополнительно: ответ, начинающийся
    с маркеров отказа из константы модуля, при непустом входе →
    `ProviderResponseInvalid` с кодом `refusal`. Список маркеров — короткий
    и точный; ложное срабатывание на реальном переводе дороже пропуска.

## Запрещено

- Писать тексты промптов в этом файле.
- Передавать ключ в query-строке URL или в теле запроса.
- Ретраить внутри провайдера.
- Логировать `req.text`, `req.context` или ответ на уровне INFO и выше.
- Использовать `temperature > 0`.
- Подавать системный промпт первым сообщением роли `user`.
- Обращаться к `privacy` напрямую: протокол реализован в базовом классе.
- Использовать этот провайдер в быстром треке (спека §9: аудио не
  поддерживается, а текстовый цикл не укладывается в бюджет 0.8–1.5 с).

## Критерии приёмки

- [ ] Успешный ответ → `TranslationResult` с непустым `translation_raw`
- [ ] Ключ уходит в заголовке `x-api-key`; в URL и в теле его нет
      (проверяется перехватывающим HTTP-клиентом)
- [ ] Заголовок `anthropic-version` присутствует в каждом запросе
- [ ] Системный промпт передан в поле `system`, а не в `messages`
- [ ] `LIVE_LITERAL`: числа, даты, суммы, имена и URL в ответе идентичны
      входным — на том же наборе `tests/fixtures/literal_20.json`, что и D2
- [ ] `POST_CLEAN` возвращает валидный JSON, `changes` заполнен;
      предзаполненная `{` восстановлена перед разбором
- [ ] `stop_reason: "max_tokens"` → `ProviderResponseInvalid`
- [ ] 429 → `ProviderRateLimited` (retryable), `retry-after` сохранён;
      401 → `ProviderAuthError`; 529 → `ProviderUnavailable` (retryable)
- [ ] Контекст из 3 сегментов присутствует в теле запроса и помечен как
      не подлежащий переводу
- [ ] Ключ `sk-CANARY` не встречается ни в одном исключении и в `repr`
- [ ] `close()` закрывает HTTP-клиент; повторный вызов безопасен
- [ ] Подмена провайдера с Gemini на Claude в конфиге не требует правок
      в вызывающем коде (тест собирает оба через общую фабрику)

## Подсказки

Минимальное тело запроса:

```json
{
  "model": "<из конфига>",
  "max_tokens": 1024,
  "temperature": 0,
  "system": "<system из D4>",
  "messages": [
    {"role": "user", "content": "<user из D4>"}
  ]
}
```

Для `POST_CLEAN` добавляется предзаполнение:

```json
"messages": [
  {"role": "user", "content": "<user из D4>"},
  {"role": "assistant", "content": "{"}
]
```

**Проверить перед реализацией:** имя модели, актуальную `anthropic-version`
и поведение предзаполнения ассистента — сверить с текущей документацией
Anthropic (`https://docs.claude.com/en/api/messages`). Имя модели берётся
из конфига.

Ловушки:
- при предзаполнении ассистента ответ приходит **без** открывающей скобки —
  склеивать вручную, иначе `json.loads` падает на каждом `post_clean`;
- предзаполнение запрещает хвостовые пробелы в тексте ассистента — строка
  ровно `"{"`;
- `content` — массив блоков, а не строка; брать первый блок с
  `type == "text"`, а не `content[0]` вслепую;
- в отличие от Gemini, фильтров безопасности с отдельным полем нет —
  отказ приходит обычным текстом, см. п. 10 «Поведение»;
- поле `usage` (`input_tokens`, `output_tokens`, поля кэша) полезно для
  экрана E5 — прокидывать в `snapshot()`, но не в `TranslationResult`.
