## Задача

Черновик генерируется на русском (спека §12), а вставлять его в чат
встречи нужно на языке собеседника. Модуль переводит `draft_ru` в целевой
язык потока и прикрепляет результат к существующей записи через
`DraftGuard.attach_translation`.

Режим перевода жёстко задан спекой §11.1: **только `live_literal`**.
Черновик содержит цены, сроки и условия; «очищенный» или «литературный»
перевод здесь недопустим по определению — это не разговорная реплика, а
проект обязательства.

Модуль отдельный, а не часть I2, по причине изоляции данных (§12): поля
`draft_*` никогда не смешиваются с `translation_*`, и путь перевода
черновика не должен проходить через тот же код, что переводит стенограмму.

## Интерфейс

```python
@dataclass(frozen=True, slots=True)
class DraftTranslateConfig:
    mode: TranslationMode = TranslationMode.LIVE_LITERAL   # не менять
    source_language: str = "ru"        # [draft].generate_language
    reject_on_drift: bool = True

class DraftTranslator:
    def __init__(self, provider: TranslationProvider, guard: DraftGuard,
                 config: DraftTranslateConfig | None = None) -> None: ...

    async def translate_draft(self, draft_id: str, draft_ru: str,
                              target_language: str) -> str | None: ...
        # None = перевод не прикреплён (см. п. 5, п. 6)

    def snapshot(self) -> dict: ...
```

## Поведение

1. **Режим только `live_literal`.** Значение приходит из конфига, но
   допустимое значение одно; любое другое → `InvariantViolation` с кодом
   `draft_mode_forbidden` при инициализации, а не при первом черновике.

2. **Контекст пустой.** `TranslationRequest.context = ()`: черновик — это
   самостоятельный текст, а не реплика в потоке. Подстановка предыдущих
   сегментов дала бы модели чужую речь как контекст ответа и открыла бы
   путь фактам из разговора в текст, который проверялся против библиотеки.

3. **`segment_id = None`.** Черновик не привязан к сегменту стенограммы.
   Привязка к `trigger_segment_id` хранится в `draft_answers`, не здесь.

4. **Совпадение языков — не работа.** `target_language` совпадает с
   `source_language` (нормализация как в C8: регистр, регион) → перевод
   не запрашивается, возвращается `draft_ru` как есть, к записи ничего не
   прикрепляется. Запрос «переведи с русского на русский» стоит денег и
   возвращает переписанный текст.

5. **Проверка дрейфа обязательна и строже, чем в стенограмме.** Результат
   прогоняется через `prompts.detect_drift`. При `reject_on_drift=True`
   любой `lost_entity` означает: перевод **не прикрепляется**, метод
   возвращает `None`, факт фиксируется в `snapshot()` и уходит в UI как
   «перевод черновика не прошёл проверку, доступен русский вариант».

   Обоснование асимметрии со стенограммой: потерянное число в переводе
   реплики собеседника — искажение записи, потерянное число в черновике
   уходит клиенту как ваше обязательство.

6. **Пустой перевод при непустом черновике** → `None` и запись в
   `snapshot()`. Исключение наружу не бросается: черновик на русском уже
   сохранён и полезен сам по себе.

7. **Прикрепление — только через `DraftGuard.attach_translation`.**
   Прямые `UPDATE draft_answers` запрещены (правило I5). Метод
   идемпотентен: повторный вызов с тем же `draft_id` перезаписывает поле,
   дубликатов не создаёт.

8. **Ошибки провайдера пробрасываются как есть.** `ProviderError` уходит
   вызывающему обработчику `JobType.DRAFT`, который решает вопрос повтора
   по `retryable`. Собственных ретраев нет (правило D1 п. 5).

9. **Протокол приватности отрабатывает провайдер** (D1). Этот модуль
   `PrivacyController` не трогает и копию профиля не держит.

10. **`snapshot()`** для E5: переведено, отклонено по дрейфу, отклонено по
    пустому ответу, пропущено по совпадению языков.

## Запрещено

- Использовать любой режим, кроме `live_literal`.
- Передавать контекст предыдущих сегментов.
- Писать в `translation_raw`, `translation_clean`, `edit_log_json`:
  это поля стенограммы, черновик в них не попадает никогда (§12,
  инвариант БД 5).
- Писать в `draft_answers` напрямую.
- Доставлять перевод куда-либо (буфер обмена, чат): доставка — только по
  действию пользователя (§12, §13).
- Прикреплять перевод, не прошедший проверку дрейфа, «с пометкой»:
  пометку в UI прочитают не всегда, а текст скопируют.
- Ретраить внутри модуля.
- Логировать `draft_ru` и перевод на уровне INFO и выше: там коммерческие
  условия.

## Критерии приёмки

- [ ] Инициализация с `mode=LIVE_SAFE` → `InvariantViolation` сразу,
      до первого вызова
- [ ] Успешный перевод → `attach_translation` вызван один раз,
      возвращён текст перевода
- [ ] `TranslationRequest`, ушедший в провайдер: `context == ()`,
      `segment_id is None`, `mode == LIVE_LITERAL`
- [ ] `target_language="ru"` при `source_language="ru"` → провайдер не
      вызывался, `attach_translation` не вызывался
- [ ] `target_language="RU"` и `"ru-RU"` распознаются как совпадение
- [ ] Перевод с пропавшей суммой → `None`, `attach_translation` не
      вызывался, счётчик отклонений в `snapshot()` вырос
- [ ] `reject_on_drift=False` → тот же перевод прикрепляется, счётчик
      всё равно растёт
- [ ] Пустой перевод при непустом черновике → `None`, без исключения
- [ ] `ProviderRateLimited` из провайдера пробрасывается наружу
      неизменённым
- [ ] Повторный вызов с тем же `draft_id` не создаёт второй записи
- [ ] Модуль не выполняет прямых запросов к БД (проверяется подменённым
      `Database` с падающими `write` и `execute`)
- [ ] `draft_ru` не встречается в логах уровня INFO и выше

## Подсказки

Сборка запроса:

```python
req = TranslationRequest(
    text=draft_ru,
    source_language=self.config.source_language,
    target_language=target_language,
    mode=TranslationMode.LIVE_LITERAL,
    context=(),
    segment_id=None,
)
result = await self.provider.translate(req)
```

Проверка дрейфа переиспользует D4, отдельной реализации не заводить:

```python
drift = prompts.detect_drift(req, result.translation_raw)
if drift and self.config.reject_on_drift:
    return None
```

Ловушки:
- `provider.translate` уже прогоняет аудит внутри базового класса (D1
  п. 7) и кладёт находки в `result.changes` — здесь достаточно
  отфильтровать `type == "lost_entity"`, повторный вызов `detect_drift`
  избыточен; оставить один путь и зафиксировать какой;
- целевой язык берётся из настроек **потока собеседника**, а не из
  настроек микрофона: черновик пишется тому, кто задал вопрос;
- UA и PL как цели перевода в MVP закрыты только текстовыми моделями
  (спека §9) — при недоступном текстовом провайдере черновик остаётся на
  русском, это штатный исход, а не ошибка;
- `snapshot()` без счётчика отклонений бесполезен: именно он покажет,
  что модель систематически теряет числа на конкретной языковой паре.
