## Задача

Слой между потоком SSE и остальным интерфейсом: держит соединение,
переживает разрывы, ведёт нормализованное состояние сессии и уведомляет
представление об изменениях.

Отдельный модуль нужен из-за одной особенности архитектуры: **один и тот
же фрагмент речи приходит дважды** — сначала черновиком быстрого трека
(`segment.partial`, 0.8–1.5 с), потом финалом точного (`segment.final`,
2.5–3.5 с), и второй вытесняет первый. Если это разбирать в коде
отрисовки, каждая вкладка UI получит свою версию логики вытеснения и свой
набор ошибок.

Состояние хранится здесь, представление (E3, E4) только читает.

## Интерфейс

```js
createStream({ url = "/events", snapshotUrl = "/api/snapshot",
               maxBackoffMs = 30000 }) -> Stream

Stream.subscribe(eventType, handler) -> unsubscribe
Stream.getState() -> { segments, drafts, status, privacy }
Stream.connect() / Stream.close()
Stream.on("connection", ({ state, attempt }) => ...)
   // state: "connecting" | "open" | "reconnecting" | "closed"
```

Нормализованное состояние:

```js
segments: Map<segmentId, {
  id, role, tStartMs, tEndMs, rawText,
  translation, mode, track,          // "fast" | "accurate"
  superseded,                        // true = вытеснен точным треком
  status: { stt, translation }
}>
drafts: Map<draftId, {
  id, triggerSegmentId, draftRu, draftTranslated,
  sources, hasGaps, copied
}>
```

## Поведение

1. **Дедупликация по `(тип, id, sequence)`.** Событие с уже виденным
   `sequence` игнорируется полностью. Это единственная защита от дублей
   при переподключении: браузер отправляет `Last-Event-ID` автоматически,
   а сервер историю не переигрывает, но дубль последнего события на
   стыке возможен.

2. **Снапшот при каждом подключении, не переигрывание.** Порядок жёсткий:
   открыть поток → получить `/api/snapshot` → применить снапшот →
   применить накопленные за это время события. События, пришедшие во
   время загрузки снапшота, буферизуются, а не отбрасываются: иначе
   реплика, сказанная в момент reconnect, исчезнет навсегда.

3. **Снапшот не затирает более новое состояние.** При применении
   сравнивается `sequence`: элемент снапшота старше уже известного —
   пропускается. Снапшот собирается на сервере не мгновенно.

4. **Вытеснение быстрого трека.** `segment.final` с тем же
   `utterance_id`, что у имеющегося `partial`, заменяет его; при
   `segment.translated` с непустым `superseded_ids` перечисленные
   элементы помечаются `superseded: true` и убираются из отрисовки.
   Удалять их из состояния сразу нельзя — событие вытеснения может
   прийти раньше самого финала.

5. **Сирота быстрого трека.** `partial` без пришедшего за 30 секунд
   `final` помечается `orphan: true` и остаётся видимым серым. Молчаливое
   исчезновение реплики хуже, чем висящий черновик: пользователь помнит,
   что фраза была.

6. **Reconnect с экспоненциальным откатом и джиттером:** 1 с, 2, 4, 8, 16,
   далее `maxBackoffMs`, ±20 % случайного разброса. Событие `connection`
   с состоянием и номером попытки уходит в UI — «Облако недоступно» и
   «UI потерял связь с сервером» это разные вещи, и пользователь должен
   их различать.

7. **`EventSource` переподключается сам, но этого мало.** Собственный
   таймер: если за `heartbeat_s × 3` не пришло ни события, ни heartbeat,
   соединение считается мёртвым, `close()` + ручной reconnect. Молча
   висящий `EventSource` — типичное поведение при засыпании ноутбука.

8. **Порядок отрисовки — по `tStartMs`**, а не по порядку прихода
   событий. Перевод сегмента приходит позже соседних финалов, и сортировка
   по времени получения перемешает стенограмму.

9. **Подписчики получают дельту, а не весь стейт.** Handler вызывается с
   изменившимся элементом; полный `getState()` — для первичной отрисовки.
   Иначе каждая вкладка перерисовывается целиком на каждой реплике.

10. **Никаких сетевых вызовов, кроме `/events` и `/api/snapshot`.**
    Команды (старт, стоп, профиль) шлёт слой панели (E4) своими POST.

## Запрещено

- Разбирать логику вытеснения в коде отрисовки.
- Отбрасывать события, пришедшие во время загрузки снапшота.
- Удалять вытесненные сегменты из состояния немедленно.
- Полагаться только на встроенный reconnect `EventSource`.
- Хранить состояние в `localStorage` или любом персистентном хранилище:
  в нём расшифровка переговоров, а `localStorage` прямо запрещён §16 для
  секретов и не даёт гарантий очистки для остального.
- Показывать разрыв связи с UI-сервером как «облако недоступно».
- Логировать содержимое событий в консоль браузера на постоянной основе:
  открытая консоль на демонстрации экрана покажет клиенту его же
  расшифровку.
- Держать более одного `EventSource` на вкладку.

## Критерии приёмки

- [ ] Дубль события с виденным `sequence` игнорируется
- [ ] События, пришедшие во время загрузки снапшота, применяются после
      него и не теряются
- [ ] Элемент снапшота старше известного состояния не затирает его
- [ ] `segment.final` вытесняет соответствующий `partial`
- [ ] `segment.translated` с `superseded_ids` помечает перечисленные
      элементы и убирает их из выдачи для отрисовки
- [ ] Событие вытеснения, пришедшее раньше финала, не приводит к потере
      сегмента
- [ ] `partial` без финала через 30 с помечается `orphan`
- [ ] Разрыв соединения → `connection: "reconnecting"`, откат
      1/2/4/8/16 с с джиттером, после восстановления — снапшот
- [ ] Отсутствие heartbeat дольше тройного интервала → принудительный
      reconnect
- [ ] Порядок сегментов в `getState()` — по `tStartMs`
- [ ] Подписчик получает только изменившийся элемент
- [ ] `close()` закрывает соединение и останавливает таймеры; повторный
      вызов безопасен
- [ ] Состояние не попадает в `localStorage`/`sessionStorage`
      (проверяется подменой API, падающей при обращении)

## Подсказки

Порядок при подключении:

```js
const buffer = [];
let ready = false;
es.onmessage = (e) => (ready ? apply(parse(e)) : buffer.push(parse(e)));
const snap = await fetch(snapshotUrl).then(r => r.json());
applySnapshot(snap);
ready = true;
buffer.splice(0).forEach(apply);
```

Ловушки:
- `EventSource` не даёт доступа к статусу ответа: 500 от сервера выглядит
  как обычный разрыв — различать по тому, дошёл ли `/api/snapshot`;
- именованные события (`event: segment.final`) не приходят в `onmessage`
  — нужен `addEventListener` на каждый тип из §7.1; забытый тип
  проявляется как «черновики не появляются», и ищется долго;
- `Last-Event-ID` браузер шлёт сам, отключить нельзя — сервер его
  принимает, но историю не переигрывает, поэтому дедупликация на клиенте
  обязательна;
- вкладка в фоне получает throttling таймеров: собственный watchdog
  heartbeat должен опираться на `Date.now()`, а не на счёт тиков.
