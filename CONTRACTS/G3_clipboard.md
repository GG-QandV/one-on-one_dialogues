## Задача

Положить текст в системный буфер обмена. Единственный путь, которым текст
покидает процесс в MVP.

Спека §13 объясняет, почему выбран именно буфер: десктопный Zoom —
нативное приложение без DOM, программная вставка в чат невозможна;
расширение браузера и эмуляция клавиатуры — тир 2. Буфер обмена даёт
100 % покрытие, включая десктопные клиенты.

Второе назначение модуля — отметить черновик как использованный:
статус `'copied'` в `draft_answers` ставится **только здесь**, по факту
действия пользователя (правило I5).

## Интерфейс

```python
class Backend(str, Enum):
    WL_COPY = "wl-copy"        # Wayland
    XCLIP = "xclip"            # X11
    XSEL = "xsel"              # X11, запасной
    NONE = "none"

@dataclass(frozen=True, slots=True)
class ClipboardConfig:
    timeout_s: float = 3.0
    backend: Backend | None = None     # None = автоопределение

async def detect_backend(cfg: ClipboardConfig) -> Backend: ...

async def copy(text: str, cfg: ClipboardConfig | None = None) -> bool: ...

async def copy_draft(guard: DraftGuard, draft_id: str, text: str,
                     cfg: ClipboardConfig | None = None) -> bool: ...
    # при успехе -> guard.mark(draft_id, "copied")

def diagnose() -> dict: ...     # что найдено в системе, для экрана E6
```

## Поведение

1. **Определение бэкенда по сессии, а не по дистрибутиву.**
   `WAYLAND_DISPLAY` установлен → `wl-copy`; иначе `DISPLAY` установлен →
   `xclip`, при его отсутствии `xsel`; ничего не найдено → `Backend.NONE`.
   Определение выполняется один раз и кэшируется на время процесса.

2. **Наличие утилиты проверяется, а не предполагается.** `wl-clipboard`
   и `xclip` не входят в базовую поставку Linux Mint. Отсутствие
   утилиты — не исключение, а `Backend.NONE` и понятная строка в
   `diagnose()`: чем ставить (`apt install wl-clipboard` /
   `apt install xclip`).

3. **`copy` возвращает `bool`, не бросает.** Провал копирования не должен
   ронять обработчик UI: пользователь нажал кнопку, кнопка не сработала,
   UI показывает это и предлагает выделить текст вручную.

4. **Таймаут обязателен.** `xclip` без перенаправления ввода-вывода
   висит, удерживая selection, и остаётся зомби-процессом до конца
   сессии. Запуск — с `timeout_s`, при превышении процесс убивается,
   возвращается `False`.

5. **Порядок в `copy_draft` жёсткий:** сначала копирование, потом
   `guard.mark(draft_id, "copied")`. Пометка ставится **только при
   `True`**. Иначе статистика «черновики, которые реально пригодились»
   превращается в статистику нажатий на кнопку.

6. **`mark` вызывается ровно один раз.** Повторное копирование того же
   черновика допустимо (пользователь копирует дважды), но `mark`
   идемпотентен на стороне I5 — дублирующий вызов допустим, обход через
   прямой `UPDATE` запрещён.

7. **Пустой текст не копируется** — `False`, без запуска процесса.
   Затирать содержимое буфера пустой строкой по ошибке пользователь не
   должен.

8. **Текст передаётся через stdin**, не аргументом командной строки.
   Аргументы видны в `ps` любому процессу пользователя — а в буфер уходят
   коммерческие условия из черновика.

9. **Горячая клавиша — не здесь.** `[delivery].clipboard_hotkey` из
   конфига обрабатывает UI-слой (E4): модуль предоставляет функцию,
   привязку делает вызывающий.

10. **Никакой автовставки.** Модуль кладёт текст в буфер и всё. Ни
    `xdotool`, ни эмуляции нажатий, ни фокуса окна — это тир 2, выключено
    по умолчанию, и в MVP кода быть не должно (§13).

## Запрещено

- Передавать текст аргументом командной строки.
- Запускать процесс без таймаута.
- Ставить `'copied'` до подтверждённого успеха копирования.
- Писать в `draft_answers` напрямую, минуя `DraftGuard.mark`.
- Эмулировать клавиатуру, управлять фокусом окон, вставлять текст в
  чужие приложения.
- Логировать копируемый текст на любом уровне: в буфер уходят цены и
  условия.
- Считать отсутствие `xclip`/`wl-copy` фатальной ошибкой запуска
  приложения: перевод и стенограмма работают и без буфера.
- Использовать блокирующий `subprocess.run` в асинхронном коде —
  только `asyncio.create_subprocess_exec`.

## Критерии приёмки

- [ ] `WAYLAND_DISPLAY` установлен, `wl-copy` доступен → `Backend.WL_COPY`
- [ ] Только `DISPLAY`, `xclip` доступен → `Backend.XCLIP`
- [ ] `xclip` отсутствует, `xsel` есть → `Backend.XSEL`
- [ ] Ни одной утилиты → `Backend.NONE`, `copy` возвращает `False`,
      `diagnose()` содержит команду установки
- [ ] Текст уходит в stdin процесса; в списке аргументов его нет
      (проверяется перехватом вызова)
- [ ] Зависший процесс убивается по `timeout_s`, `copy` → `False`
- [ ] Пустой текст → `False`, процесс не запускался
- [ ] `copy_draft` при успехе вызывает `guard.mark(draft_id, "copied")`
      ровно один раз
- [ ] `copy_draft` при провале копирования `mark` не вызывает
- [ ] Копируемый текст не встречается в логах ни на одном уровне
- [ ] Модуль не импортирует `xdotool`-обвязку и не запускает процессов,
      кроме выбранного бэкенда (проверяется белым списком в тесте)

## Подсказки

Запуск бэкенда:

```python
proc = await asyncio.create_subprocess_exec(
    *ARGS[backend], stdin=asyncio.subprocess.PIPE,
    stdout=asyncio.subprocess.DEVNULL, stderr=asyncio.subprocess.DEVNULL)
try:
    await asyncio.wait_for(proc.communicate(text.encode()), cfg.timeout_s)
except asyncio.TimeoutError:
    proc.kill()
    return False
return proc.returncode == 0

ARGS = {
    Backend.WL_COPY: ("wl-copy",),
    Backend.XCLIP: ("xclip", "-selection", "clipboard"),
    Backend.XSEL: ("xsel", "--clipboard", "--input"),
}
```

Ловушки:
- `xclip` держит selection, пока жив процесс-владелец: после `communicate`
  он завершается, и содержимое буфера в X11 может исчезнуть — на этот
  случай в `diagnose()` стоит рекомендовать `wl-clipboard` или менеджер
  буфера (`clipman`, `parcellite`); это ограничение X11, а не дефект;
- Linux Mint Cinnamon по умолчанию X11, поэтому основной путь —
  `xclip`, а `wl-copy` — для пользователей на Wayland-сессии;
- `stdout`/`stderr` обязательно в `DEVNULL`: незакрытые дескрипторы дают
  зомби-процессы к концу часовой встречи;
- перевод строки в конце текста Zoom и Meet трактуют как отправку
  сообщения — хвостовой `\n` из черновика обрезать перед копированием.
