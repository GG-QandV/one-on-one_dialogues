# CONTRACTS/ — задания для агентов-исполнителей

Задача A2 роадмапа. Один файл = одна задача = один агент = один контекст.

---

## Как пользоваться

**Агент-исполнитель** получает: этот README + свой файл контракта +
`INTERFACES.md` + падающий тест из `tests/`. Больше ничего. Спека и роадмап
целиком не выдаются: контракт обязан быть самодостаточным, а ссылки на
пункты спеки нужны для эскалации, а не для чтения.

**Агент-архитектор** при добавлении задачи заполняет все разделы шаблона.
Контракт без раздела «Запрещено» или без критериев приёмки не выдаётся.

**Ревьюер (ChatGPT 5.6)** сверяет код с контрактом и с `INTERFACES.md`.
Расхождение = возврат со ссылкой на конкретный пункт.

## Шаблон контракта

```markdown
# <ID> — <краткое название>

| | |
| :-- | :-- |
| Файл | `app/.../name.py` |
| Уровень | Junior / Junior+ / Middle / Middle+ / Senior |
| Оценка | NNN LOC, N тестов |
| Зависит от | список готовых модулей |
| Блокирует | что нельзя начать без этой задачи |
| Пункт спеки | §N |

## Задача
Одним абзацем: что модуль делает и зачем существует.

## Интерфейс
Точные сигнатуры. Копируются из INTERFACES.md без изменений.

## Поведение
Пронумерованные правила. Каждое проверяемо тестом.

## Запрещено
Явный список. Нарушение = возврат без обсуждения.

## Критерии приёмки
Чеклист. Все пункты обязаны стать тестами.

## Подсказки
Известные ловушки, форматы данных, примеры ответов API.
```

## Правила для всех исполнителей

1. **Задание = контракт + падающий тест.** Нет теста — не начинать, а
   запросить его у Архитектора.
2. **Запрет заглушек.** `pass`, `TODO`, `return None` в местах реальной
   логики, `assert True` в тестах — автоматический возврат по CI
   (`scripts/check_no_stubs.sh`). Не можешь реализовать — верни отказ с
   причиной, не имитацию.
3. **Запрет расширения области.** Правки вне файлов своей задачи запрещены.
   Нужна правка чужого модуля — заявка Архитектору, не самостоятельное
   изменение.
4. **Ссылка на спеку.** Нетривиальное решение сопровождается ссылкой на
   пункт. Решение без пункта — кандидат на пробел в спеке, эскалируется.
5. **Один контекст — одна задача.** Не помещается вместе с контрактом и
   тестом — вернуть на дробление.
6. **Честный отчёт.** «Полностью выполнено» — только при 100% прохождении
   контракт-тестов. Частично — явный список невыполненного.
7. **Конфиг вместо хардкода.** Любая константа, влияющая на поведение, —
   в `config.toml`. Литералы в коде допустимы только для форматов
   (16000 Гц, 20 мс) и уже зафиксированы в `app/audio/pcm.py`.
8. **Профиль конфиденциальности — сквозной инвариант.** Любой код,
   отправляющий данные наружу, обязан пройти протокол из `INTERFACES.md` §1.3
   (require → вызов → validate → запись). Отсутствие проверки — блокирующий
   дефект независимо от блока.

## Что считается провалом этапа

| Нарушение | Почему блокирующее |
| :-- | :-- |
| Отчёт о готовности при непройденных тестах | Разрушает доверие ко всем отчётам агентов |
| Обход неизменяемости `raw_text` или `privacy_profile` | Стенограмма перестаёт быть аудитом |
| Ключ BYOK в БД, файле, URL или логе | Утечка учётных данных клиента |
| Отправка аудио наружу в конфиденциальном профиле | Нарушение обещания пользователю |
| Результат быстрого трека в `raw_text` или экспорте | Черновик выдаётся за проверенный текст |
| Черновик с фактом вне библиотеки без `has_gaps` | Пользователь озвучит клиенту выдуманную цену |
| Доставка черновика без действия пользователя | То же, но автоматически |
| Молчаливое изменение архитектурного решения | Ревью теряет смысл |
| Тест подогнан под реализацию | Тест перестаёт быть контрактом |
