## Задача

Хранилище разделов библиотеки фактов, из которых генератор черновиков
(I2) берёт материал. Спека §12: RAG не используется, раздел вставляется в
запрос целиком, потолок — **30 000 токенов**, при превышении 150 тыс. —
тир 2.

Отсюда две ответственности: оценка размера до отправки в облако и
неизменность текста между запросами. Второе не менее важно первого:
библиотека вставляется префиксом запроса и кэшируется провайдером; любая
незаметная нормализация текста между вызовами обнуляет кэш и переводит
сессию на полную оплату префикса при каждом вопросе.

## Интерфейс

```python
@dataclass(frozen=True, slots=True)
class LibraryContext:
    id: str
    name: str
    domain: str | None
    content_text: str
    token_estimate: int
    updated_at: str            # ISO-8601 UTC

class LibraryTooLarge(InvariantViolation):
    """code='library_too_large'; в args — оценка и лимит, без текста."""

class FactLibrary:
    def __init__(self, db: Database, *, max_tokens: int = 30000) -> None: ...
    async def list(self) -> list[LibraryContext]: ...
    async def get(self, context_id: str) -> LibraryContext: ...
    async def upsert(self, name: str, domain: str | None,
                     content_text: str) -> str: ...
    async def delete(self, context_id: str) -> None: ...
    def estimate_tokens(self, text: str) -> int: ...
    def check_limit(self, text: str,
                    max_tokens: int | None = None) -> tuple[bool, int]: ...
```

## Поведение

1. **`estimate_tokens` — эвристика без внешних зависимостей.** Тянуть
   `tiktoken` или SDK провайдера ради оценки нельзя: у Gemini и Claude
   разные токенизаторы, а точность здесь не нужна — нужна
   консервативность. Формула: доля кириллицы `c` в тексте,
   `tokens ≈ len(text) * (c / 2.5 + (1 - c) / 4)`, округление вверх.
   Кириллица дороже латиницы примерно в полтора раза у обоих провайдеров.
   Оценка сознательно завышена; погрешность документируется как ±25 %.

2. **`check_limit`** возвращает `(ok, estimate)` и **не бросает**. Это
   функция для UI: панель настроек показывает пользователю размер до
   сохранения.

3. **`upsert` бросает `LibraryTooLarge`** при превышении лимита, с
   фактической оценкой и лимитом в аргументах. Молчаливое усечение
   запрещено: пользователь должен узнать, что часть фактов не уедет в
   запрос, до встречи, а не по пустому черновику посреди неё.

4. **Нормализация текста — минимальная и однократная, при записи:** снять
   BOM, привести `CRLF`/`CR` к `LF`, обрезать хвостовые пробелы строк,
   обрезать края документа. Всё. Ни переносов, ни схлопывания пустых
   строк, ни изменения регистра. При чтении текст не трогается вообще:
   `get()` дважды подряд обязан вернуть побайтово одинаковый
   `content_text`.

5. **`token_estimate` считается при записи** и хранится в строке таблицы.
   `get`/`list` его не пересчитывают — иначе смена формулы задним числом
   разойдётся с тем, что видел пользователь.

6. **Идентификация раздела — по `id`.** `upsert` обновляет запись, если
   раздел с таким `name` уже существует (имя уникально), иначе создаёт
   новый и возвращает сгенерированный `id`. `name` пустой или из одних
   пробелов → `InvariantViolation`.

7. **`list()` не тянет тексты целиком.** В списке для UI `content_text`
   заполняется пустой строкой, размер берётся из `token_estimate`. Полный
   текст отдаёт только `get()`. Три раздела по 30k токенов в списке — это
   лишние сотни килобайт на каждое открытие панели.

8. **`get` на несуществующий `id`** → `InvariantViolation` с кодом
   `library_context_not_found`.

9. **`delete` проверяет ссылки:** если раздел указан в
   `sessions.library_context_id` хотя бы одной сессии — удаление
   запрещено, `InvariantViolation` с кодом `library_context_in_use`.
   Прослеживаемость черновиков (§12) требует, чтобы источник оставался
   доступным для разбора после встречи.

10. **Все записи — через `db.write` одной транзакцией.** Прямых
    `sqlite3.connect` нет (правило `INTERFACES.md` §1.2).

11. **Ни сети, ни вызовов провайдеров.** Модуль ничего не знает ни о
    Gemini, ни о Claude.

## Запрещено

- Усекать `content_text` при превышении лимита.
- Пересчитывать или нормализовать текст при чтении.
- Тянуть внешние токенизаторы и SDK провайдеров.
- Отдавать `content_text` в `list()`.
- Класть текст библиотеки в логи любого уровня: там коммерческие условия,
  цены и внутренние договорённости.
- Хранить более одной активной версии раздела: версионирование — тир 2,
  в MVP `upsert` перезаписывает.
- Реализовывать здесь разбиение на чанки и поиск: RAG в MVP не
  используется (§12).

## Критерии приёмки

- [ ] `estimate_tokens` на латинском тексте 4000 знаков → ≈1000 (±25 %)
- [ ] `estimate_tokens` на кириллическом тексте 4000 знаков → ≈1600 (±25 %)
- [ ] `check_limit` на тексте сверх лимита → `(False, estimate)`, без
      исключения
- [ ] `upsert` сверх лимита → `LibraryTooLarge`, в аргументах оценка и
      лимит, текста библиотеки в аргументах нет
- [ ] `upsert` записывает `token_estimate` и `updated_at` в ISO-8601 UTC
- [ ] `get()` дважды подряд → побайтово идентичный `content_text`
- [ ] `CRLF` на входе → в БД `LF`; повторный `upsert` того же текста не
      меняет `content_text`
- [ ] `upsert` с существующим `name` обновляет запись, не создаёт вторую
- [ ] Пустой `name` → `InvariantViolation`
- [ ] `list()` возвращает `content_text == ""` и корректные
      `token_estimate`
- [ ] `get` на неизвестный `id` → `InvariantViolation`
- [ ] `delete` раздела, привязанного к сессии → `InvariantViolation`
- [ ] Модуль не выполняет сетевых вызовов (проверяется отсутствием
      импортов `httpx`, `aiohttp`)

## Подсказки

Оценка токенов:

```python
def estimate_tokens(self, text: str) -> int:
    if not text:
        return 0
    cyr = sum(1 for ch in text if "\u0400" <= ch <= "\u04FF")
    share = cyr / len(text)
    return math.ceil(len(text) * (share / 2.5 + (1 - share) / 4))
```

Проверка ссылок при удалении:

```sql
SELECT 1 FROM sessions WHERE library_context_id = ? LIMIT 1
```

Ловушки:
- «30 000 токенов» — это лимит на **раздел**, а не на всю библиотеку:
  разделов может быть много, в запрос уходит один (`sessions.library_context_id`);
- пользователь будет вставлять текст из Word — там неразрывные пробелы
  (`\u00A0`) и мягкие переносы; в нормализацию их **не** включать, они
  часть текста, но учитывать, что они попадут в оценку;
- `updated_at` пишется в UTC (правило времени в `INTERFACES.md` §0), не в
  локальной зоне: иначе сортировка в UI поедет после смены времени;
- лимит по умолчанию берётся из конфига `[draft].library_max_tokens`,
  значение 30000 в сигнатуре — только страховка для тестов.
