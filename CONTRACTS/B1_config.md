# B1 — конфигурация: загрузка, валидация, запись из панели

| | |
| :-- | :-- |
| Файл | `app/config.py` |
| Уровень | Junior+ |
| Оценка | 270 LOC, 14 тестов |
| Зависит от | `app/errors.py` (готов) |
| Блокирует | **все модули** — каждый берёт параметры отсюда |
| Пункт спеки | §19 |

## Задача

Прочитать `config.toml`, проверить значения, разложить в типизированные
секции и уметь записать изменения обратно из панели управления.

Принцип спеки §19 сформулирован одной фразой: **ноль хардкода**. Все
параметры, влияющие на поведение, — в конфиге. Это касается и порогов
VAD, и окна контекста, и имён моделей, и адреса UI.

Обратная сторона принципа: конфиг с опечаткой не должен ронять
приложение через час встречи. Все проверки — при загрузке, до старта
чего бы то ни было.

## Интерфейс

```python
@dataclass(frozen=True, slots=True)
class Config:
    privacy: PrivacySection
    provider: ProviderSection          # translation / realtime / draft
    stt: SttSection
    streams: dict[str, StreamSection]  # "microphone", "meeting"
    vad: VadSection
    latency: LatencySection
    translation_context: ContextSection
    draft: DraftSection
    retention: RetentionSection
    memory: MemorySection
    delivery: DeliverySection
    ui: UiSection
    source_path: Path

def load(path: Path) -> Config: ...
def load_or_default(path: Path) -> Config: ...     # создаёт файл из дефолтов
def validate(raw: dict) -> list[str]: ...          # список проблем, не бросает
def update(path: Path, changes: dict[str, Any]) -> Config: ...
def to_toml(config: Config) -> str: ...
def defaults() -> dict: ...
```

## Поведение

1. **Чтение через `tomllib`** (стандартная библиотека). Запись — своим
   сериализатором: `tomllib` умеет только читать, а тянуть `tomli-w` ради
   десятка секций не нужно.

2. **Дефолты — из спеки §19 дословно.** Файл `config.example.toml` (B6)
   генерируется из `defaults()`, а не пишется руками: расхождение примера
   и кода обнаруживается на второй неделе и стоит часа отладки.

3. **Отсутствующий файл** → `load_or_default` создаёт его из дефолтов и
   возвращает конфиг. `load` в этом случае бросает `ConfigError`. Два
   разных поведения нужны: первый запуск и явная передача пути — разные
   ситуации.

4. **Отсутствующая секция или ключ — не ошибка**, подставляется дефолт.
   Ошибка — только неверное **значение**: конфиг переживает обновление
   версии, добавившей новые ключи.

5. **Валидация значений, обязательный минимум:**

   | Параметр | Правило |
   | :-- | :-- |
   | `privacy.default_profile` | `open` / `confidential` |
   | `provider.translation.active` | `gemini` / `claude` / `custom` |
   | `provider.realtime.enabled_profiles` | подмножество `["open"]` — realtime в конфиденциальном профиле запрещён (§9) |
   | `stt.mode` | `file_per_segment` (единственный режим MVP, §7) |
   | `vad.silence_close_ms` | 800–1200 включительно (§19, комментарий) |
   | `vad.segment_min_s` | > 0 и < `segment_max_s` |
   | `translation.context.*` | окна ≥ 1, `short_chars` < `long_chars` |
   | `draft.library_max_tokens` | 1 000 – 150 000 (§12: свыше — тир 2) |
   | `draft.translate_mode` | только `live_literal` (§11.1) |
   | `retention.audio` | `after_stt` / `24h` / `7d` / `keep` |
   | `memory.high_mb` | < `max_mb`, оба > 512 |
   | `ui.port` | 1024–65535 |
   | `ui.host` | не петлевой адрес → предупреждение, не ошибка |
   | языки потоков | ISO 639-1 из списка §4: `en`, `es`, `ru`, `uk`, `pl` |
   | цели перевода `uk`, `pl` | предупреждение: тир 2, обслуживаются только текстовыми моделями |

6. **`validate` возвращает список строк и ничего не бросает.** Панель
   управления показывает пользователю все проблемы разом, а не первую.
   `load` вызывает `validate` и бросает `ConfigError` со всем списком.

7. **Секреты в конфиг не пишутся никогда.** Ключи провайдеров живут в
   `KeyStore` (G2). Если в загруженном файле обнаружен ключ (по
   паттернам G1) — значение **не читается** в конфиг, выдаётся
   предупреждение уровня WARNING с указанием секции и требованием убрать
   его из файла.

8. **`update` — атомарная запись:** временный файл рядом, `fsync`,
   `os.replace`. Прерывание записи посреди операции не должно оставить
   пользователя без конфига. Перед записью — та же валидация; невалидные
   изменения не применяются, файл не трогается.

9. **`update` сохраняет то, чего не знает.** Незнакомые секции и ключи из
   исходного файла переносятся в новый как есть. Иначе панель управления
   вычистит параметры, добавленные будущей версией.

10. **Комментарии не сохраняются** — это осознанное ограничение:
    сохранение комментариев требует потокового TOML-редактора. Вместо
    этого `to_toml` пишет свои комментарии-подсказки к каждой секции из
    констант модуля.

11. **Горячая перезагрузка не реализуется.** Изменение конфига применяется
    при старте сессии; параметры, требующие перезапуска (порт UI, пути
    моделей), помечаются в `to_toml` комментарием. Тихая смена порогов
    посреди встречи хуже, чем явное «примените после перезапуска».

## Запрещено

- Хардкодить любое значение, влияющее на поведение, вне `defaults()`.
- Читать конфиг напрямую из других модулей (`tomllib.load` где-либо, кроме
  `config.py`) — проверяется грепом в ревью.
- Писать ключи провайдеров в файл или отдавать их в объекте `Config`.
- Бросать исключение из `validate`.
- Перезаписывать файл целиком без сохранения незнакомых секций.
- Писать конфиг не атомарно.
- Применять невалидные изменения «частично».
- Реализовывать hot reload.

## Критерии приёмки

- [ ] Дефолты совпадают со спекой §19 (сравнение с фикстурой
      `tests/fixtures/config_spec_19.toml`, скопированной из спеки)
- [ ] Отсутствующий файл: `load_or_default` создаёт его, `load` бросает
      `ConfigError`
- [ ] Отсутствующая секция → дефолт, без ошибки
- [ ] Незнакомый ключ → сохраняется при `update`, в `Config` не попадает
- [ ] `vad.silence_close_ms = 500` → ошибка валидации с указанием
      допустимого диапазона
- [ ] `retention.audio = "forever"` → ошибка с перечислением допустимых
      значений
- [ ] `memory.high_mb >= max_mb` → ошибка
- [ ] `draft.translate_mode = "live_safe"` → ошибка
- [ ] `provider.realtime.enabled_profiles = ["confidential"]` → ошибка
- [ ] `ui.host = "0.0.0.0"` → предупреждение, загрузка проходит
- [ ] Три ошибки в файле → `validate` возвращает три строки, `ConfigError`
      содержит все три
- [ ] Ключ вида `sk-…` в файле: в `Config` не попадает, WARNING выдан,
      значение не логируется
- [ ] `update` при падении посреди записи (подменённый `os.replace`,
      бросающий исключение) оставляет исходный файл нетронутым
- [ ] `to_toml(load(path))` даёт файл, который снова загружается в
      эквивалентный `Config` (round-trip)

## Подсказки

Атомарная запись:

```python
tmp = path.with_suffix(path.suffix + ".tmp")
tmp.write_text(text, encoding="utf-8")
with open(tmp, "rb") as f:
    os.fsync(f.fileno())
os.replace(tmp, path)          # атомарно в пределах одной ФС
```

Ловушки:
- `tomllib.load` требует бинарного режима (`open(path, "rb")`) — на
  текстовом падает с невнятной ошибкой;
- TOML различает целые и вещественные: `segment_min_s = 1` и `= 1.0` дают
  разные типы, валидация должна принимать оба и приводить к `float`;
- секции `[streams.microphone]` и `[streams.meeting]` разбираются в
  словарь по имени, а не в два фиксированных поля: в тире 2 потоков может
  стать больше;
- пути (`stt.model`, каталоги сессий) разворачиваются относительно
  каталога конфига, а не текущей рабочей директории — иначе запуск из
  systemd и из терминала дают разные результаты;
- значение `[vad].silence_close_ms = 1000` в §19 и `silence_close_ms = 800`
  в `SegmentConfig` (реализовано) расходятся: конфиг — источник правды,
  дефолт датакласса используется только в тестах. Это расхождение стоит
  зафиксировать в PR явно.
