## Задача

Держать состояние доступности облачных провайдеров и после восстановления
догонять непереведённое.

Инвариант, ради которого модуль существует (спека §8, пункт 7):
**недоступность облака не останавливает локальный STT и запись.** Речь
распознаётся и пишется в `raw_text` независимо от того, отвечает ли
переводчик. Переводы — отдельная очередь, которая догоняет.

Второй смысл модуля — не долбить упавший провайдер. Без него каждый
сегмент честно отрабатывает 3 попытки с backoff, и при часовом падении
провайдера сессия тратит тысячи бесполезных запросов и заполняет очередь.

## Интерфейс

```python
class ProviderState(str, Enum):
    AVAILABLE = "available"
    DEGRADED = "degraded"        # временный отказ, идёт откат
    BLOCKED = "blocked"          # авторизация: сам не восстановится

@dataclass(frozen=True, slots=True)
class OfflineConfig:
    failures_to_degrade: int = 3
    probe_initial_s: float = 5.0
    probe_max_s: float = 300.0
    probe_factor: float = 2.0
    catch_up_batch: int = 200

class OfflineGate:
    def __init__(self, config: OfflineConfig | None = None,
                 *, clock: Callable[[], float] = time.monotonic) -> None: ...
    def mark_unavailable(self, provider: str, err: ProviderError) -> None: ...
    def mark_available(self, provider: str) -> None: ...
    def is_degraded(self, provider: str | None = None) -> bool: ...
    def should_attempt(self, provider: str) -> bool: ...
    async def catch_up(self, db: Database, queue: JobQueue) -> int: ...
    def snapshot(self) -> dict: ...
```

## Поведение

1. **Учёт по провайдерам раздельно.** Падение Gemini не переводит в
   деградацию Claude. `is_degraded()` без аргумента отвечает про активный
   набор: `True`, если деградировали все зарегистрированные провайдеры.

2. **Переход в `DEGRADED`.** После `failures_to_degrade` подряд идущих
   `mark_unavailable` с retryable-ошибкой (`ProviderUnavailable`,
   `ProviderRateLimited`). Одиночный сетевой сбой деградацией не считается.

3. **`ProviderAuthError` → сразу `BLOCKED`**, без счётчика. Повтор не
   поможет: нужен новый ключ от пользователя (G2). Из `BLOCKED` выход
   только через явный `mark_available` — его вызывает панель настроек
   после ввода ключа, а не таймер.

4. **`ProviderResponseInvalid` состояние не меняет.** Битый ответ — это
   проблема сегмента или промпта, а не доступности. Иначе один странный
   сегмент выключит перевод всей сессии.

5. **Пробы (half-open).** В `DEGRADED` `should_attempt` возвращает `False`,
   пока не истёк интервал отката, и `True` ровно один раз по его истечении.
   Интервал растёт `probe_initial_s * probe_factor ** n` до `probe_max_s`.
   Успех пробы → `mark_available` вызывает потребитель, счётчики сброшены.

6. **`mark_available` идемпотентен** и сбрасывает счётчик отказов, номер
   пробы и интервал.

7. **`catch_up` ставит задачи, а не переводит.** Выбирает сегменты
   `track='accurate'` с `translation_status IN ('pending','failed')`,
   сортирует по `t_start_ms` возрастанию, ставит `JobType.TRANSLATE`
   пачкой не более `catch_up_batch`, возвращает число поставленных.
   Идемпотентность — через `idempotency_key = segment_id`: повторный
   вызов дубликатов не создаёт.

8. **Порядок догона — хронологический.** Пользователь читает стенограмму
   сверху вниз; догон с конца даёт рваную картину.

9. **`catch_up` не вызывается на каждый успех.** Точка вызова одна:
   переход провайдера `DEGRADED → AVAILABLE`. Вызывающий код (`main`)
   отвечает за то, чтобы не запускать догон параллельно сам с собой.

10. **Часы инжектируются** параметром `clock`. Тесты интервалов отката без
    инжекции превращаются в `sleep` и в мигающие проверки.

11. **`snapshot()`** для экрана E5: по каждому провайдеру — состояние,
    число отказов подряд, код последней ошибки (**без текста и без
    ключа**), секунды до следующей пробы, время последнего успеха, счётчик
    поставленных догоном задач.

## Запрещено

- Останавливать, ставить на паузу или как-либо трогать STT: это нарушение
  инварианта §8.7. Приостановка облачных задач — прерогатива
  `DegradationCascade` (F2, готов), а не этого модуля.
- Вызывать провайдеров: `OfflineGate` не делает сетевых вызовов вообще.
- Переводить сегменты внутри `catch_up`.
- Ставить задачи мимо `JobQueue.enqueue` (прямыми INSERT в `jobs`).
- Реализовывать собственный backoff для отдельного запроса: попытки внутри
  задачи считает `JobQueue`, здесь — только состояние провайдера.
- Класть в `snapshot()` и в логи текст ошибки провайдера и ключ.
- Считать `ProviderResponseInvalid` признаком недоступности.
- Хранить состояние в БД: `OfflineGate` живёт в памяти процесса, после
  перезапуска состояние восстанавливается естественным путём — первым
  запросом.

## Критерии приёмки

- [ ] 2 отказа подряд → `AVAILABLE`; 3-й → `DEGRADED`
- [ ] Успех между отказами обнуляет счётчик (2 отказа, успех, 2 отказа →
      всё ещё `AVAILABLE`)
- [ ] `ProviderAuthError` при нулевом счётчике → сразу `BLOCKED`
- [ ] Из `BLOCKED` таймер не выводит: `should_attempt` = `False` и через
      час модельного времени
- [ ] `ProviderResponseInvalid` не меняет состояние
- [ ] В `DEGRADED` `should_attempt` → `False`, после `probe_initial_s` →
      один `True`, следующий вызов снова `False`
- [ ] Интервал растёт 5 → 10 → 20 … и упирается в `probe_max_s`
- [ ] Падение Gemini не влияет на состояние Claude
- [ ] `is_degraded()` без аргумента → `True` только когда деградировали все
- [ ] `catch_up` ставит задачи в хронологическом порядке `t_start_ms`
- [ ] Повторный `catch_up` без новых сегментов возвращает 0 и не создаёт
      дубликатов (проверка по `idempotency_key`)
- [ ] `catch_up` при 500 подходящих сегментах и `catch_up_batch=200`
      ставит 200
- [ ] Ни один тест не обнаруживает вызова STT-компонентов
- [ ] Ключ `sk-CANARY` и текст ошибки отсутствуют в `snapshot()`

## Подсказки

Состояние на провайдер — небольшой мутабельный датакласс внутри модуля
(наружу не отдаётся):

```python
@dataclass(slots=True)
class _Entry:
    state: ProviderState = ProviderState.AVAILABLE
    consecutive_failures: int = 0
    probe_index: int = 0
    next_probe_at: float = 0.0
    last_error_code: str | None = None
    last_success_at: float | None = None
```

Выборка для догона:

```sql
SELECT id FROM segments
WHERE session_id = ?
  AND track = 'accurate'
  AND translation_status IN ('pending', 'failed')
ORDER BY t_start_ms ASC
LIMIT ?
```

Ловушки:
- `time.monotonic` и `time.time` не взаимозаменяемы: для интервалов только
  монотонные часы, иначе перевод системного времени ломает откат;
- `mark_unavailable` может прийти из нескольких обработчиков
  одновременно — счётчик инкрементируется в одном месте, без
  read-modify-write через `await` посередине;
- задачи, поставленные догоном, обязаны иметь `idempotent=True`, иначе
  `JobQueue.recover()` после перезапуска их не повторит;
- `catch_up` на большой сессии — не «догнать всё сразу»: батч ограничен
  намеренно, следующая пачка уедет после разбора текущей.
