## Задача

Список прошедших сессий и выгрузка их стенограмм. Работа постфактум:
пользователь после встречи открывает историю, просматривает сессию,
экспортирует в нужном формате, при необходимости запускает повторный
перевод отдельного сегмента.

Вкладка не участвует в живой встрече — она читает завершённые сессии из
БД через серверные роуты. Единственное требование, которое здесь легко
нарушить: экспорт содержит **только точный трек** (§8.3, критерий
приёмки 13), и вкладка обязана это гарантировать, не собирая экспорт
сама, а получая его от сервера, где данные идут через `export_view`.

## Интерфейс

```js
createHistory({ container, commands }) -> History

History.mount()
History.unmount()

commands.listSessions({ limit, before? }) -> Promise<Array<SessionRow>>
commands.getSession(sessionId) -> Promise<{ session, segments, drafts }>
commands.exportSession(sessionId, format) -> Promise<Blob>   // txt|json|srt|vtt
commands.retranslateSegment(segmentId) -> Promise<void>      // опционально
```

## Поведение

1. **Список сессий** — из `listSessions`: заголовок встречи, время начала
   и конца, статус (`active`/`finished`/`aborted`), профиль по умолчанию,
   провайдер, число сегментов. Пагинация по `before` (курсор по времени),
   не загрузка всех сессий разом.

2. **Просмотр сессии** — `getSession` отдаёт сегменты и черновики.
   Отрисовка стенограммы переиспользует представление карточек (E3) в
   режиме «только чтение»: те же поля (`raw_text`, перевод, профиль,
   таймкод), без живых обновлений и без черновиков-подписок.

3. **Экспорт — четыре формата** (§14, G4): TXT, JSON, SRT, VTT. Кнопка на
   формат либо выпадающий выбор. Файл приходит от сервера готовым
   (`Blob`), клиент только инициирует скачивание. Клиент **не собирает**
   форматы сам — иначе рискует включить быстрый трек, который сервер
   отфильтровал.

4. **Имя файла** осмысленное: заголовок встречи + дата + расширение.
   Пустой заголовок → дата и время. Не `export.txt`.

5. **JSON — полный след.** Пользователь должен понимать, что JSON — это
   audit-выгрузка (raw_text, переводы, edit_log, профили, черновики,
   ошибки), а TXT/SRT/VTT — для чтения и субтитров. Короткая подпись у
   выбора формата.

6. **Повторный перевод сегмента — опционально.** Если E1 даёт роут, из
   просмотра сессии можно перезапустить перевод отдельного сегмента
   (например, тот, что упал с ошибкой). Ставит задачу на сервере,
   результат придёт обновлением. Без роута — функции нет.

7. **Активная сессия в списке — особый случай.** Идущая сессия
   (`status: active`) показывается, но помечена «идёт»; экспорт активной
   сессии допустим (частичная выгрузка), но с пометкой «сессия не
   завершена, данные неполны».

8. **Не ведёт живого состояния.** В отличие от других вкладок, история
   не подписывается на поток событий вовсе (кроме, возможно, обновления
   после `retranslateSegment`). Данные — разовые запросы, не поток.

9. **Пустая история — валидна.** Ни одной сессии → понятное «сессий пока
   нет», не пустой экран и не ошибка.

10. **Ничего не удаляет и не меняет.** История — чтение и экспорт.
    Удаление сессий, если понадобится, — отдельная функция с
    подтверждением, не в MVP.

## Запрещено

- Собирать форматы экспорта на клиенте: только серверный экспорт через
  `export_view`, иначе в выгрузку попадёт быстрый трек (§8.3, §21.13).
- Подставлять `translation_clean` вместо `translation_raw` или наоборот
  при отображении: поля раздельны.
- Показывать черновики смешанными со стенограммой: `draft_*` отдельно от
  `translation_*` (§8.5).
- Грузить все сессии разом без пагинации.
- Именовать экспорт обезличенно (`export.txt`).
- Удалять или изменять данные сессии.
- Экспортировать активную сессию без пометки о неполноте.

## Критерии приёмки

- [ ] Список сессий с заголовком, временем, статусом, числом сегментов
- [ ] Пагинация по `before`; не грузит все сессии сразу
- [ ] Просмотр сессии показывает сегменты в режиме чтения
- [ ] Четыре формата экспорта доступны; файл приходит от сервера
- [ ] Клиент не собирает форматы сам (проверяется: экспорт вызывает
      `exportSession`, а не строит текст в JS)
- [ ] Имя файла содержит заголовок/дату, не обезличено
- [ ] Активная сессия помечена «идёт»; её экспорт — с пометкой неполноты
- [ ] Пустая история → понятное сообщение, не ошибка
- [ ] `retranslateSegment` (если есть роут) ставит задачу, результат
      обновляет отображение
- [ ] `unmount()` очищает состояние; повторный вызов безопасен

## Подсказки

Скачивание готового Blob от сервера:

```js
async function download(sessionId, format) {
  const blob = await commands.exportSession(sessionId, format);
  const url = URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = url;
  a.download = makeFilename(session, format);   // заголовок+дата+ext
  a.click();
  URL.revokeObjectURL(url);
}
```

Ловушки:
- соблазн собрать TXT из уже загруженных `getSession`-сегментов на
  клиенте — прямой путь включить быстрый трек, который сервер
  отфильтровал через `export_view`; экспорт всегда серверный;
- `URL.revokeObjectURL` обязателен после скачивания — иначе Blob-и
  копятся в памяти вкладки;
- переиспользование карточек E3 в режиме чтения требует, чтобы E3 умел
  рисовать из статичных данных без подписки на поток — если E3 жёстко
  завязан на `stream`, нужна лёгкая read-only версия рендера карточки,
  согласовать с автором E3;
- активная сессия в истории — редкий, но реальный случай (пользователь
  открыл историю во время встречи); не падать на `ended_at: null`;
- пагинация `before` работает по времени; при одинаковом времени начала
  добавить вторичный ключ (id), иначе курсор зациклится.
