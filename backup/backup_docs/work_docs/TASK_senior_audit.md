# Задание Senior-агенту: аудит дрейфа (Part II ревизии)

Ты — ревизор. Твоя работа **только читать код и сверять со спекой**. Ты
ничего не исправляешь. Каждый найденный дефект оформляешь строкой в
отчёте с цитатой кода и пунктом спеки; исправлять будет другой агент по
твоему диагнозу.

Причина разделения: тот, кто нашёл проблему, склонен «быстро поправить»
и в процессе принять микрорешение, которого нет в спеке. Именно так E3
разошёлся с E2. Аудит выявляет, реализация исправляет — роли не
смешиваются.

## Формат отчёта

Один файл `docs/AUDIT_partII.md`. На каждый пункт — ровно одна из
формулировок:

```
[N] ok
[N] ДЕФЕКТ — файл:строка — <что не так> — спека §<X> требует <что> — код делает <что>
[N] НЕ ПРОВЕРЯЕМО — <почему, что нужно чтобы проверить>
```

Никаких «вероятно ok», «выглядит правильно». Либо подтверждено чтением,
либо дефект, либо честно «не проверяемо без X».

## Раздел C — известный дрейф (§7 ревизии)

Это точки, где дрейф уже подозревается. Не переоткрывать решения —
проверить, что код соответствует **уже принятому** решению.

## Порядок и границы

1. Раздел A целиком — до всего. Каждый BLOCKER немедленно в отчёт.
2. Раздел B — параллельно можно, но после A.
3. Раздел C — по мере касания модулей.

**Не делать:**
- не исправлять найденное — только документировать;
- не переоткрывать решения раздела C;
- не помечать `ok` без чтения кода;
- не считать зелёный тест доказательством инварианта, пока не прочитал,
  что именно тест утверждает.

**Выход:** `docs/AUDIT_partII.md` с 15 пунктами разделов A–B и таблицей
раздела C, каждый в одном из трёх статусов. Список BLOCKER-ов вынести в
начало файла отдельным блоком — это вход для агентов-исправителей.
