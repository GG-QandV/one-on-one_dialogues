# E5 — вкладка «Диагностика»

| | |
| :-- | :-- |

| Уровень | Middle |
| Оценка | 240 LOC, 8 тестов |
| Зависит от | E2 (`stream.js`), E1-routes (`/api/snapshot`), F1/D7/G2/degradation (snapshot-данные) |
| Блокирует | отладку живого теста |
| Пункт спеки | §14 (вкладка диагностики), §15 (память), §17 (health) |

## Задача

Показать внутреннее состояние системы: память, деградацию, доступность
провайдеров, TTL ключа, уровни аудио, задержки. Это экран, по которому
находят причину, когда на встрече что-то пошло не так: тишина в потоке,
пропавший перевод, выросшая задержка.

Данные приходят готовыми из `snapshot()` разных модулей (F1 память, D7
offline, G2 byok, degradation каскад) через `/api/snapshot` и события
`status`. Вкладка ничего не вычисляет — она отображает то, что модули уже
измерили, и **честно показывает деградированные источники**, а не
маскирует их под исправные.

## Интерфейс

```js
createDiagnostics({ container, stream, commands }) -> Diagnostics

Diagnostics.mount()
Diagnostics.unmount()

commands.fetchSnapshot() -> Promise<snapshot>   // /api/snapshot
commands.probeProvider(name) -> Promise<...>     // опционально, ручная проба
```

## Поведение

1. **Память (из F1 `snapshot`).** Текущее потребление, пик, расстояние до
   порогов `high_mb`/`max_mb`, источник (`cgroup` / `vmrss`). Если
   `source == "vmrss"` — **явное предупреждение** «дочерний whisper не
   учитывается, значение занижено» (F1: деградированный источник не
   маскируется). График истории — из `history()`, если сервер отдаёт.

2. **Деградация (из degradation каскада).** Текущий `Level`
   (NORMAL/LATENCY/MEMORY_SOFT/MEMORY_HARD) и какие действия активны
   (укорочены сегменты, приостановлены облачные задачи, форсирована tiny-
   модель). Уровень выше NORMAL — заметно, с пояснением, что именно
   деградировало.

3. **Провайдеры (из D7 offline `snapshot`).** По каждому: состояние
   (AVAILABLE/DEGRADED/BLOCKED), число отказов подряд, код последней
   ошибки (**без текста и без ключа** — D7 их не отдаёт), секунды до
   следующей пробы, счётчик задач, поставленных догоном. `BLOCKED`
   (авторизация) — отдельно и заметно: сам не восстановится, нужен ключ.

4. **Ключ (из G2 `snapshot`).** Наличие, TTL, флаг `expiring_soon`. Сам
   ключ и маску здесь **не показывать** — маска живёт в настройках (E7),
   диагностике достаточно «есть/нет + сколько осталось».

5. **Аудио-уровни (из capture `snapshot`).** RMS/пик по каждому потоку
   (микрофон, собеседник). Это ключевой элемент для отладки настройки
   PipeWire: нулевой уровень в потоке = узел не подключён. Показывать
   живой индикатор, а не число раз в минуту.

6. **Задержки (из событий `status`).** Медиана быстрого и точного трека,
   `backlog_ms` (глубина очереди). Превышение бюджета (1500/3000 мс из
   конфига) — визуально выделять: это первый признак деградации, видимый
   раньше, чем каскад сработает.

7. **Health (из `/health`, `/ready`).** Простой индикатор: процесс жив,
   зависимости готовы. Отличать «сервис запущен, но не готов» (БД не
   открыта, STT не инициализирован) от «готов».

8. **Обновление по событию и по опросу.** События `status` обновляют
   задержки и уровень в реальном времени. Остальное (память, провайдеры,
   ключ) — периодический `fetchSnapshot` с интервалом из конфига, потому
   что эти модули событий не шлют. Интервал разумный (единицы секунд), не
   долбить сервер.

9. **Ручная проба провайдера — опционально.** Если E1 даёт роут
   `probeProvider`, кнопка «проверить провайдера» инициирует пробу
   (полезно при `DEGRADED`, чтобы не ждать автоматической). Без роута —
   кнопки нет.

10. **Ничего не решает и не чинит.** Диагностика только показывает.
    Действия (revoke ключа, переключение профиля) — в E6/E7, не здесь.
    Единственное исключение — ручная проба провайдера (п. 9), и та
    инициирует серверное действие, а не выполняет его в UI.

## Запрещено

- Показывать ключ или его маску (маска — в E7).
- Показывать текст ошибок провайдера (D7 их не отдаёт; выдумывать
  нельзя).
- Маскировать `source == "vmrss"` под исправный: заниженная память без
  предупреждения хуже, чем честное «источник деградировал».
- Вычислять деградацию, память, задержки на клиенте: всё приходит из
  snapshot модулей.
- Чинить что-либо (revoke, переключение) — это другие вкладки.
- Опрашивать сервер чаще, чем задано конфигом.
- Показывать уровни аудио числом раз в минуту вместо живого индикатора:
  для отладки PipeWire нужна реакция в реальном времени.

## Критерии приёмки

- [ ] Память показывает текущее/пик/пороги/источник из F1 snapshot
- [ ] `source == "vmrss"` → видимое предупреждение о занижении
- [ ] `Level > NORMAL` → показан уровень и активные действия каскада
- [ ] Провайдер `BLOCKED` выделен отдельно от `DEGRADED`
- [ ] Код ошибки провайдера показан без текста и без ключа
- [ ] Ключ: наличие и TTL, без маски и без значения
- [ ] Аудио-уровни — живой индикатор по обоим потокам; нулевой уровень
      различим
- [ ] Задержка сверх бюджета визуально выделена
- [ ] `/ready` false при живом `/health` → состояние «запущен, не готов»
- [ ] `status`-события обновляют задержки без полного опроса
- [ ] Опрос snapshot не чаще интервала из конфига
- [ ] `unmount()` останавливает опрос и снимает подписки; повторный
      вызов безопасен

## Подсказки

Раздельные источники обновления:

```js
// быстрое — из событий
stream.subscribe('status', (d) => updateLatency(d));
// медленное — опрос, эти модули событий не шлют
this._timer = setInterval(async () => {
  const snap = await commands.fetchSnapshot();
  updateMemory(snap.memory);
  updateProviders(snap.offline);
  updateKey(snap.byok);
}, cfg.diagnosticsPollMs);
```

Ловушки:
- `unmount()` обязан очистить `setInterval` — забытый таймер продолжит
  долбить сервер после ухода с вкладки;
- аудио-уровень приходит в snapshot как число, но для «живого»
  индикатора его надо опрашивать чаще прочего — либо отдельный быстрый
  опрос уровней, либо (лучше) сервер шлёт уровни событием; уточнить у E1,
  не решать в UI;
- `vmrss`-предупреждение легко потерять среди цифр — оно должно быть
  заметным, потому что меняет доверие ко всему блоку памяти;
- код ошибки провайдера (`last_error_code`) — это код вроде `429` или
  `timeout`, не текст; если в snapshot пришёл текст, это дефект D7, а не
  повод показать его тут.
