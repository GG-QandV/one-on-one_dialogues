### 2. Главное правило

**Контракт — это задание целиком. Ничего не додумывай.**

| Ситуация                            | Что делать                                                       |
| ----------------------------------- | ---------------------------------------------------------------- |
| В контракте есть сигнатура функции  | Скопировать её как есть, до символа                              |
| В контракте нет какого-то поведения | Не реализовывать. Спросить                                       |
| Кажется, что в контракте ошибка     | Не исправлять. Спросить                                          |
| Кажется, что можно сделать красивее | Не делать. Контракт написан под инварианты, которых ты не видишь |

Отсутствие инициативы здесь — правильное поведение, а не недостаток.

### 3. Шаги по каждому файлу

1. Прочитать контракт **целиком**, включая раздел «Подсказки» — там перечислены ловушки.
2. Открыть пункты спеки из шапки контракта.
3. Выписать все чекбоксы из «Критериев приёмки» — это твой список тестов.
4. Написать тесты. **До кода.** Каждый чекбокс = минимум один тест.
5. Написать код так, чтобы тесты прошли.
6. Прогнать `pytest`, `ruff check`, `mypy --strict`.
7. Пройти по разделу «Запрещено» построчно и проверить каждый пункт.

Если после шага 6 хоть один чекбокс не закрыт — это не «доделаю потом», это причина не открывать PR.

### 4. Чего не делать никогда

* Не менять `raw_text` — ни регистр, ни пунктуацию, ни пробелы. Это неизменяемая запись для аудита.
* Не писать в базу напрямую. Запись — через владеющий модуль.
* Не логировать текст сегментов, черновиков и содержимое библиотеки.
* Не писать числа в код: пороги, лимиты и таймауты берутся из конфига.
* Не использовать `row["column"]` напрямую — только через `row_get`.
* Не расширять сигнатуру, чтобы «стало удобнее». Её ждут три других модуля.
* Не заменять исключения из `app/errors.py` своими.

### 5. Ловушка в каждом твоём файле

| ID  | Ловушка, которая ломает всё                                                                                 |
| --- | ----------------------------------------------------------------------------------------------------------- |
| B3  | `sqlite3.Row` при отсутствии столбца бросает `IndexError`, а не отдаёт `None`. Всё чтение — через `row_get` |
| B3  | `stt_confidence` — отрицательное число. `if confidence:` ошибочно, сравнивай с `None` явно                  |
| B1  | `tomllib.load` требует открытия файла в бинарном режиме (`"rb"`)                                            |
| B1  | `validate` не бросает исключений — возвращает список проблем. Бросает только `load`                         |
| G4  | Данные берутся **только** из `export_view`. Свой `SELECT` — гарантированное нарушение инварианта спеки      |
| G4  | SRT требует `\r\n`, VTT требует `\n`. Это не вкусовщина, плееры ломаются                                    |
| G3  | Текст передаётся процессу через stdin. Через аргументы командной строки нельзя — их видно в `ps`            |
| G3  | Процесс запускается только с таймаутом, иначе `xclip` зависает зомби-процессом                              |
| E3  | Черновик и проверенный перевод не показываются одновременно — второй **заменяет** первый                    |
| E3  | Своего состояния в модуле нет. Всё приходит из `stream.js` (E2) готовым                                     |

### 6. Когда останавливаться и спрашивать

Спрашивай сразу, не пытаясь решить сам:

* контракт противоречит спеке или другому контракту;
* в контракте нет ответа на возникший вопрос;
* нужно изменить сигнатуру;
* критерий приёмки непонятно как проверить тестом;
* файл вырос больше чем в полтора раза от оценки LOC.

Вопрос стоит десять минут. Молча принятое решение ломает модули, которые ждут твою сигнатуру, и обнаруживается через неделю.

### 7. Чек-лист перед PR

```
[ ] Все чекбоксы «Критериев приёмки» закрыты тестами
[ ] pytest — зелёный
[ ] ruff check — чисто
[ ] mypy --strict — чисто
[ ] Раздел «Запрещено» пройден построчно
[ ] Числовых литералов порогов в коде нет
[ ] Текст сегментов и черновиков в логах не появляется
[ ] Сигнатуры совпадают с контрактом посимвольно
```

Заголовок PR: `[ID] короткое описание`. В теле — список закрытых чекбоксов и отдельно то, что закрыть не удалось, с причиной. Незакрытый пункт, названный честно, — нормально. Незакрытый пункт, о котором не сказано, — возврат PR.

| ID  | Зависит от                  | Кто пишет    | Можно начинать?         |

**Оговорка по B3.** Он зависит не от мидла, а от `B2` (`migrations/`), который ещё не написан. Значения перечислений обязаны совпадать со строками в DDL. Варианты:

* писать B3 сейчас по спеке §8, а сверку с DDL добавить тестом позже (риск переименования 1–2 констант, ~15 минут правки);
* сначала B2, потом B3 — B2 junior-уровня и короткий (200 LOC).

Второй путь чище.

**Как гасить простой на E3.** Пока мидл делает E2, юниор может подготовить статическую часть: `cards.css`, HTML-разметку карточки из контракта, словарь подписей ролей, форматирование таймкода. Это ~40 % объёма E3 и не требует готового `stream.js` — нужен только контракт полей состояния, а он в E3 уже зафиксирован.

**Рекомендуемая очередь юниора:** `B2 → B3 → B1 → G3 → G4 → (разметка E3) → E3`.

Единственная точка синхронизации с мидлом — E3. Если мидл задержит E2, юниор не простаивает: у него впереди пять задач.
