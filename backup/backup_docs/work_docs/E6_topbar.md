| Зависит от | E2 (`stream.js`), E1-routes (POST-команды), C8 (индикатор языка) |

## Задача

Постоянная панель над вкладками: профиль конфиденциальности с
переключателем, индикатор языка и его конфликта, состояние провайдера
перевода, состояние соединения с UI-сервером, кнопки старт/стоп сессии.

Это единственное место, где пользователь **действует** во время встречи:
переключает профиль, видит, работает ли облако, замечает конфликт языка.
Всё остальное в UI — чтение. Поэтому topbar совмещает две природы:
читает состояние из E2 (как вкладки) **и** шлёт команды на сервер (как
панель настроек).

Переключатель профиля — самый ответственный элемент всего интерфейса.
Переход в `confidential` обязан оборвать облачную аудио-сессию; пока
обрыв не подтверждён событием, переключатель не должен показывать, что
профиль уже сменился, — иначе пользователь заговорит о конфиденциальном,
считая канал закрытым, когда он ещё открыт.

## Интерфейс

```js
createTopbar({ container, stream, commands }) -> Topbar

Topbar.mount()
Topbar.unmount()

// commands — тонкая обёртка над POST-роутами E1, инъектируется:
commands.setPrivacy(profile) -> Promise<{ profile, teardown_ms }>
commands.startSession(meetingTitle?) -> Promise<{ session_id }>
commands.stopSession() -> Promise<void>
```

## Поведение

1. **Профиль — оптимистично, но с откатом.** По клику переключатель
   уходит в состояние `switching` (визуально — «переключение…»,
   переключатель заблокирован), шлётся `commands.setPrivacy`. Реальная
   смена подтверждается **событием** `privacy.changed` из потока, не
   ответом на POST: ответ говорит «команда принята», событие — «профиль
   и teardown фактически применены». До события переключатель не
   показывает новый профиль как активный.

2. **Teardown виден.** Событие `privacy.changed` несёт `teardown_ms` —
   сколько заняло закрытие облачного канала. При переходе в
   `confidential` это показывается явно («канал закрыт за 180 мс»):
   пользователю нужна уверенность, что обрыв произошёл, а не обещан.

3. **Ошибка переключения.** POST вернул ошибку или событие не пришло за
   разумное время (таймаут из конфига) → переключатель откатывается в
   прежний профиль, показывается ошибка. Молчаливый откат недопустим:
   пользователь думает, что переключил, а профиль прежний.

4. **Индикатор языка** берётся из состояния сегментов (E2): активный
   язык оригинала. При конфликте (`conflict: true` в данных сегмента,
   из C8) — значок и подсказка с текстом `note` (уже русский,
   человекочитаемый). Кнопки «исправить язык» нет: автопереключение
   запрещено спекой §4, panel только показывает.

5. **Состояние провайдера** из события `status` (`state`,
   `degradation_level`). Три различимых состояния: работает, деградация
   (облако отвечает с перебоями — жёлтый), недоступно (красный). «Облако
   недоступно» и «UI потерял сервер» — **разные** индикаторы: первое из
   `status`, второе из состояния соединения E2.

6. **Состояние соединения** из `stream.on('connection', ...)`:
   `connecting` / `open` / `reconnecting` / `closed`. `reconnecting`
   показывается явно — при засыпании ноутбука это норма, и пользователь
   не должен путать это с падением сервера.

7. **Старт/стоп сессии.** Кнопка старта неактивна, если сессия идёт;
   стопа — если сессии нет. Состояние сессии — из `status.state`.
   Двойной клик по старту не создаёт две сессии (кнопка блокируется на
   время запроса).

8. **Профиль по умолчанию** при первой отрисовке — из `/api/snapshot`
   (`default_privacy_profile`), не захардкожен. До получения снапшота
   переключатель в состоянии `loading`, не в произвольном профиле.

9. **Не ведёт своего состояния сегментов.** Как все вкладки: читает
   `stream.getState()` и подписывается. Собственное состояние topbar —
   только UI-состояние переключателя (`switching`/`error`), не данные
   сессии.

10. **Точечное обновление.** Событие `status` перерисовывает индикатор
    провайдера, не всю панель. `privacy.changed` — переключатель.
    Языковой конфликт — значок языка.

## Запрещено

- Показывать новый профиль как активный до события `privacy.changed`.
- Откатывать переключатель молча при ошибке.
- Смешивать «облако недоступно» и «нет связи с UI-сервером» в один
  индикатор.
- Предлагать автопереключение языка при конфликте.
- Хардкодить профиль по умолчанию.
- Слать `setPrivacy` повторно, пока предыдущее переключение не
  разрешилось (событием или ошибкой).
- Вести собственное состояние сегментов или ходить в сеть мимо
  `commands`.
- Логировать в консоль содержимое событий на постоянной основе.
- Создавать сессию повторным кликом во время запроса.

## Критерии приёмки

- [ ] Клик по профилю → состояние `switching`, `commands.setPrivacy`
      вызван один раз
- [ ] Профиль показывается активным только после `privacy.changed`,
      не после ответа POST
- [ ] `privacy.changed` с `teardown_ms` → значение показано при переходе
      в `confidential`
- [ ] Ошибка POST или таймаут события → откат в прежний профиль +
      видимая ошибка
- [ ] Повторный клик во время `switching` игнорируется
- [ ] `conflict: true` → значок и подсказка с `note`; кнопки смены языка
      нет
- [ ] `status` с деградацией → жёлтый индикатор провайдера;
      недоступность → красный
- [ ] `connection: reconnecting` → отдельный индикатор, отличный от
      «облако недоступно»
- [ ] Старт неактивен при идущей сессии, стоп — при отсутствии
- [ ] Двойной клик по старту создаёт одну сессию
- [ ] Профиль по умолчанию берётся из снапшота
- [ ] `unmount()` снимает подписки; повторный вызов безопасен

## Подсказки

Оптимистичное переключение с подтверждением по событию:

```js
async function onProfileClick(target) {
  setSwitchState('switching');
  try {
    await commands.setPrivacy(target);       // POST принят
    // активным профиль станет в обработчике privacy.changed,
    // НЕ здесь — здесь только сняли блокировку по таймауту
  } catch (e) {
    setSwitchState('error');
    revertToggle();
  }
}
stream.subscribe('privacy.changed', (d) => {
  applyProfile(d.profile);
  showTeardown(d.teardown_ms);
  setSwitchState('idle');
});
```

Ловушки:
- `teardown_ms` может быть 0 при переходе из `confidential` в `open`
  (закрывать нечего) — это не ошибка, показывать нейтрально;
- индикатор соединения опирается на событие `connection` из E2, а
  индикатор облака — на `status` из потока: перепутать источники значит
  показать «сервер упал», когда упало облако, и наоборот;
- профиль в topbar — глобальный (текущий), а профиль в карточке (E3) —
  историчный (на момент сегмента). Это разные вещи, не синхронизировать
  их: карточки хранят свой профиль намеренно;
- кнопка старта до получения снапшота — в состоянии `loading`, а не
  «доступна»: клик по ней до готовности сервера создаст гонку.
