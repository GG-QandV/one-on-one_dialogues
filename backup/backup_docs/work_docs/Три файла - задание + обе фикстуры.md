**Находка при сборке фикстуры промптов**

Промпт `post_clean` (§11.3) заканчивается строкой `Верни JSON: {"clean_text": "...", "changes": [...]}`. На ней `str.format` падает с `KeyError`. Подстановка языков возможна только через `str.replace` по именам плейсхолдеров — ни `format`, ни f-строки. В контракте D4 этой ловушки не было, добавил в задание и в комментарий фикстуры.

**Почему 11 негативных случаев из 20**

Проверяется не только «поймал потерю», но и «не сорвался на корректном переводе»: перестановка чисел в предложении, `30 000` против `30,000`, `7,5` против `7.5`, транслитерация «Иванов → Ivanov», короткое «Да». Ложное срабатывание на них — такой же провал приёмки, как пропуск потерянного числа.

Отдельно случай 18: чисел нет вообще, срабатывание только по обвалу длины, `expect_originals` пуст — проверяет, что модуль умеет пометить дрейф без конкретной пропавшей сущности.

**Ограничения выполнения**

1. `prompts_spec_11.json` собран мной из `/mnt/project/SPEC_speech_local_v2.md` строки 348–380. Это и есть «ручная копия из спеки», требуемая контрактом. **Сверьте один раз глазами** — если спека в репозитории новее загруженной в проект, фикстура унаследует старый текст, и тест зафиксирует неверный эталон.
2. `drift_20.json` — мой набор, не выписка из спеки. Пороги в нём согласованы с `AuditConfig` из D4 (`length_ratio_min=0.6`, `check_names=False`). При смене порогов случаи 18 и 19 нужно пересчитать.
3. Случай 16 (`7,5%` → `7%`) требует, чтобы `extract_numbers` из `drafts/guardrails.py` умел дробные с запятой. Модуль реализован, но это его поведение я не проверял — если не умеет, случай 16 провалится не по вине D4.
