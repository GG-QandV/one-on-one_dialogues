# I3 — детектор вопроса: спека, тесты, встраивание

Файл: `app/drafts/trigger.py` (готов, 15/15 на примерах). Ниже — спека
поведения, план тестов и точка встраивания в конвейер.

---

## Спека

### Интерфейс
```python
def is_question(text: str, language: str) -> tuple[bool, float]
```
Синхронная, без БД и сети. `(решение, уверенность 0..1)`.

### Правила (решения владельца)

1. **Языки: только en, es.** Для любого другого — `(False, 0.0)`.
   Расширение (ru/uk/pl/…) — tier 1.X. Порог языка — первые 2 символа
   кода (`en`, `es`), регистр не важен.

2. **Ловим вопрос по трём признакам:**
   - знак `?` или `¿` в тексте;
   - вопросительное слово в начале (en: what/how/why/…, es: qué/cómo/…,
     плюс составное «por qué»);
   - инверсия вспомогательного/модального глагола в начале (en: do/can/
     is/…, es: puede/podría/hay/…).

3. **НЕ ловим императив-пинок без `?`.** Реплики «tell me…», «cuénteme…»,
   «расскажите…» — запрос действия, но вопросом без знака НЕ считаются
   (решение владельца). С `?` — ловим (пользователь мог поставить знак
   осознанно).

4. **Порог низкий (`0.5`).** Пропуск вопроса дороже лишнего черновика:
   лишний игнорируется во вкладке, пропущенный лишает функции. Порог
   зашит внутрь — вызывающий получает готовый `bool`, не настраивает.

### Шкала уверенности
| Признак | conf |
| :-- | --: |
| `?` + вопросительное слово | 0.95 |
| `?` + инверсия aux | 0.90 |
| `?` без распознанной структуры | 0.85 |
| вопросительное слово без `?` | 0.70 |
| инверсия aux без `?` | 0.60 |
| императив без `?` | 0.20 (не вопрос) |
| прочее | 0.10 (не вопрос) |

### Что запрещено
- Ловить императивы без `?`.
- Детектить языки вне {en, es} (вернуть False, не гадать).
- Дедуп по схожести текста: повторный вопрос = новый сегмент = новый
  черновик (осознанно). Защита от дубля ОДНОГО сегмента — на уровне
  UNIQUE(trigger_segment_id) и idempotency_key, не здесь.
- Любой ввод-вывод: функция чистая и синхронная.

## План тестов (`tests/test_trigger_I3.py`)

Позитив (ловим):
- `«How much does it cost?»`/`«¿Cuánto cuesta?»` → True, conf ≥ 0.9
- `«How much does it cost»` без знака → True (q-слово)
- `«Do you support X»` без знака → True (инверсия)
- `«Por qué usan SQLite?»` → True (составное)

Негатив (не ловим):
- `«Tell me the price.»`/`«Cuénteme…»` → False (императив без ?)
- `«We need this done fast.»` → False (утверждение)
- `«Nous voulons…»` (fr) → (False, 0.0) (язык вне списка)
- `«»` пусто → (False, 0.0)

Граница:
- `«Tell me the price?»` → True (императив, НО со знаком)
- регистр/пробелы: `«  HOW  much…»` → True

## Встраивание (для следующего шага — DRAFT-обработчик)

I3 сам ничего не ставит. Его вызывает конвейер после записи accurate-
сегмента. Точка — рядом с постановкой TRANSLATE в `_on_stt_result`.

### Ключевой фильтр: только поток собеседника
Черновик готовится на вопрос ОППОНЕНТА, не на свою речь. Значит
`is_question` вызывается ТОЛЬКО для сегментов из потока `role='meeting'`,
не `role='microphone'`. Роль берётся из `audio_streams` по `stream_id`
(тот же JOIN, что в TRANSLATE).

### Эскиз постановки (в `_on_stt_result`, после enqueue TRANSLATE)
```python
        # DRAFT: только вопросы собеседника (role='meeting').
        if role == "meeting":
            from app.drafts.trigger import is_question
            is_q, _conf = is_question(raw_text, meeting_language)
            if is_q:
                await self.jobs.enqueue(
                    JobType.DRAFT,
                    segment_id=seg.id,
                    idempotency_key=f"dr:{seg.id}",
                )
```
- `meeting_language` = язык потока meeting (тот же источник, что
  source_language в TRANSLATE-JOIN).
- `idempotency_key=f"dr:{seg.id}"` — дубль ОДНОГО сегмента отсекается;
  повторный вопрос — другой seg.id — проходит.

> Это эскиз для DRAFT-обработчика (следующий модуль). Сам обработчик
> `JobType.DRAFT` (I2.generate → guard.verify → guard.store) here НЕ
> пишется — он идёт после I3, как TRANSLATE-обработчик шёл после D-слоя.

### Точки сверки при встраивании
| Что | Где |
| :-- | :-- |
| Имя переменной роли и языка в `_on_stt_result` | main.py |
| Есть ли `role`/язык под рукой или нужен JOIN | main.py / audio_streams |
| `JobType.DRAFT` в enum очереди | queue.py (в схеме jobs.type есть 'draft') |

## Порядок
1. `trigger.py` → в `app/drafts/` (готов).
2. Тесты I3 → прогнать, назвать число.
3. Встраивание в `_on_stt_result` (фильтр role='meeting') — можно вместе
   с DRAFT-обработчиком, чтобы не ставить задачи в пустоту.

> Если ставить постановку DRAFT ДО написания обработчика — задачи
> `JobType.DRAFT` будут копиться без исполнителя. Либо встраивать
> постановку и обработчик одним заходом, либо сначала обработчик, потом
> включить постановку. Рекомендую: I3 (модуль+тесты) сейчас, а
> встраивание — в связке с DRAFT-обработчиком следующим шагом.
