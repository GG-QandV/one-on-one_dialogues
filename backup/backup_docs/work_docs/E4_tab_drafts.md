# E4 — вкладка «Черновики ответов»

| | |
| :-- | :-- |
| Файл | `app/ui/static/js/tab_drafts.js` |
| Уровень | Middle |
| Оценка | 240 LOC, 8 тестов |
| Зависит от | E2 (`stream.js`), E1-routes, G3 (буфер обмена) |
| Блокирует | сценарий черновиков в живом тесте |
| Пункт спеки | §12 (черновики), §13 (доставка), §10.3 |

## Задача

Показать сгенерированные черновики ответов и дать пользователю
скопировать выбранный в буфер обмена. Черновик — самый опасный элемент
продукта: он выглядит как ответ менеджера, но собран моделью, и
выдуманная цена, попавшая в чат встречи, — это обязательство перед
клиентом.

Отсюда три требования, встроенных в спеку §12 и обязательных для UI:
черновик **не доставляется автоматически** (только по действию
пользователя), пробелы в фактах (`has_gaps`) **видны явно**, источники
(разделы библиотеки) **показаны** для проверки.

Вкладка читает состояние из E2, копирует через G3, статус «скопировано»
ставит только по факту действия.

## Интерфейс

```js
createDrafts({ container, stream, commands }) -> Drafts

Drafts.mount()
Drafts.unmount()

commands.copyDraft(draftId, text) -> Promise<boolean>   // -> G3, mark copied
commands.retranslateDraft(draftId) -> Promise<void>     // опционально
```

## Поведение

1. **Карточка черновика** содержит: русский текст (`draft_ru`), перевод на
   язык встречи (`draft_translated`, если пришёл), источники (`sources` —
   разделы библиотеки), явный флаг пробелов (`has_gaps`), связь с
   вопросом (`trigger_segment_id` — какая реплика клиента вызвала
   черновик).

2. **Пробелы видны, а не спрятаны.** `has_gaps: true` → заметная пометка
   «есть пробелы в фактах» и текст `gap_note`, если он пришёл. Это не
   деталь — это разница между «ответ готов» и «ответ неполон, проверь
   перед отправкой». Прятать пометку в мелкий шрифт нельзя.

3. **Источники показаны.** `sources` — список разделов, на которые
   опирался черновик. Пустой `sources` при отсутствии пробелов — сигнал
   дефекта (I2 такой черновик не должен был отдать), показать как
   предупреждение, а не молча скрыть.

4. **Копирование — только по клику.** Кнопка «Копировать» вызывает
   `commands.copyDraft`, который идёт в G3. Никакого автокопирования, ни
   при появлении черновика, ни при выборе, ни по таймеру (§12: доставка
   только по действию пользователя).

5. **Что копируется — выбор пользователя.** Русский оригинал или перевод.
   Кнопки раздельные («копировать RU», «копировать перевод»). Если
   перевод не прошёл проверку дрейфа (I4 вернул `None`) — кнопка перевода
   неактивна, доступен только русский, с пометкой «перевод не прошёл
   проверку».

6. **Статус «скопировано» — по факту.** `copyDraft` вернул `true` →
   карточка помечается «скопировано» (это ставит `DraftStatus.COPIED`
   через G3→guard). Вернул `false` (нет xclip/wl-copy) → показать «не
   удалось скопировать, выделите текст вручную», статус не менять.

7. **Порядок и актуальность.** Черновики в порядке появления (по времени
   триггера). Новый черновик (`draft.created`) добавляется сверху или
   снизу консистентно; перевод (`draft.translated`) дозаполняет
   существующую карточку, не создаёт новую.

8. **Связь с репликой.** По `trigger_segment_id` — возможность показать,
   на какой вопрос клиента отвечает черновик (подсветить реплику во
   вкладке перевода или показать её текст в карточке). Это помогает
   пользователю решить, релевантен ли черновик.

9. **Не ведёт своего состояния.** Как все вкладки: подписка на
   `draft.created`/`draft.translated`, чтение `stream.getState().drafts`,
   отрисовка. Логика — в E2.

10. **Игнорированные черновики.** Пользователь может пометить черновик
    неактуальным (не копировал) — это `DraftStatus.IGNORED`. Простое
    скрытие/сворачивание, чтобы лента черновиков не копилась за час
    встречи. Опционально для MVP, но предусмотреть место.

## Запрещено

- Автоматически копировать черновик куда-либо (§12, §21.11).
- Прятать `has_gaps` или показывать его незаметно.
- Скрывать пустой `sources` вместо предупреждения.
- Ставить статус «скопировано» до успеха `copyDraft`.
- Копировать через что-либо, кроме G3 (`commands.copyDraft`).
- Прикреплять перевод, не прошедший проверку дрейфа, как готовый к
  копированию (I4 вернул `None` → кнопка перевода неактивна).
- Вести собственное состояние черновиков или разбирать события в обход
  E2.
- Доставлять черновик в чат встречи, эмулировать вставку (тир 2).
- Логировать текст черновика в консоль.

## Критерии приёмки

- [ ] Карточка показывает `draft_ru`, `sources`, `has_gaps`,
      `trigger_segment_id`
- [ ] `has_gaps: true` → заметная пометка + `gap_note`
- [ ] Пустой `sources` без пробелов → предупреждение, не скрытие
- [ ] Кнопка «Копировать» вызывает `copyDraft`; автокопирования нет
      (проверяется отсутствием вызова при `draft.created`)
- [ ] `copyDraft` → `true` → карточка «скопировано»
- [ ] `copyDraft` → `false` → сообщение об ошибке, статус не изменён
- [ ] Перевод не прошёл проверку (нет `draft_translated`) → кнопка
      перевода неактивна, русский доступен
- [ ] `draft.translated` дозаполняет карточку, не создаёт новую
- [ ] Черновики в консистентном порядке по времени триггера
- [ ] `unmount()` снимает подписки; повторный вызов безопасен
- [ ] Текст черновика не попадает в `console`

## Подсказки

Копирование строго по действию:

```js
copyBtn.addEventListener('click', async () => {
  const ok = await commands.copyDraft(draft.id, draft.draft_ru);
  if (ok) markCopied(draft.id);
  else showCopyError();          // нет xclip/wl-copy — G3 вернул false
});
// НИГДЕ нет copyDraft в обработчике draft.created
```

Ловушки:
- соблазн «скопировать сразу, как появился черновик» — прямое нарушение
  §21.11; критерий приёмки это проверяет отдельным тестом;
- `has_gaps` приходит из I2 уже с учётом согласования (I2 форсит `true`,
  если в тексте «нет данных»); UI не пересчитывает, только показывает;
- если `draft_translated` отсутствует — это либо перевод ещё не пришёл
  (ждать), либо не прошёл проверку дрейфа (I4 вернул `None`, не придёт
  никогда); различить по статусу/событию, не держать кнопку в вечном
  «ожидании»;
- `trigger_segment_id` связывает черновик с репликой в другой вкладке —
  подсветка требует координации с E3, но саму координацию делает не
  напрямую, а через общее состояние E2;
- лента черновиков за час встречи вырастает — сворачивание
  игнорированных (п. 10) не косметика, а условие читаемости к концу
  встречи.
