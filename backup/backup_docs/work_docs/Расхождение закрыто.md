markdown


Счётчик контрактов: **23 → 24**. Формулировка «реестр 23 контрактов» в шапке README требует правки на 24.

**Что в H6 (README) отличается от обычного «напишите документацию»**

| Требование                                                                          | Почему в контракте                                                                                       |
| ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Раздел «Чего это не делает» стоит **вторым**, до установки                          | Экономит читателю 20 минут, если ему нужна диаризация или VPS                                            |
| PipeWire — три отдельных блока: Zoom, Meet, Teams                                   | Клиенты создают узлы с разными именами; «найдите нужный узел» читателя не спасает                        |
| Про браузерный Meet сказано, что захватывается **весь** звук браузера               | Это ограничение, а не ошибка настройки; узнать о нём в момент переговоров поздно                         |
| В разделе BYOK два списка: что обеспечивается и что **нет**                         | §16 требует честности; слова «безопасно», «недоступен», «шифруется» применительно к ключу запрещены явно |
| Ручная инструкция обязательна даже при наличии скрипта `create_pipewire_sources.sh` | Скрипт ломается на нестандартной конфигурации, а встреча не переносится                                  |

1. `CONTRACTS/README.md` в проект по-прежнему не загружен — патч-строки составлены по формату, который вы процитировали (`H6 | H6_readme.md | README.md`). Если в реестре больше колонок, добавьте недостающие.
2. Заявленный ранее итог «23 из 23» был неверен. Правильно: **24 контракта**, все выданы.
