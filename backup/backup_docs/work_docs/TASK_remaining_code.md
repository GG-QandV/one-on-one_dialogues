## F1 — `app/watchdog/memory.py` [Middle+]

Контракт `F1_watchdog_memory.md` — полный, следовать ему. **Но: в
`degradation.py` (F2, готов) УЖЕ ЕСТЬ `MemoryReader`** с cgroup/vmrss и
логикой локации cgroup. Это меняет задачу F1.

### Находка в коде F2 (прочитан)
`degradation.py` содержит класс `MemoryReader` с:
- `_locate_cgroup()` — путь cgroup v2 из `/proc/self/cgroup`;
- `current_mb()` — cgroup → VmRSS фолбэк;
- `source` + WARNING при vmrss.

То есть **базовое чтение памяти уже реализовано** внутри F2. F1 не должен
его переписывать с нуля.

### Что делает F1 сверх готового MemoryReader
Контракт F1 требует БОЛЬШЕ, чем F2-шный MemoryReader:
1. **Периодический опрос** (F2-reader только разовое `current_mb`) —
   `start()/stop()`, интервал 2с.
2. **История** (`history_size=300`) для графика E5 — F2-reader её не ведёт.
3. **Дочерние процессы в vmrss-режиме** — F2-reader в vmrss меряет только
   себя (`VmRSS` своего процесса). F1 обязан суммировать whisper-детей
   (главная ловушка контракта). **Это ключевое отличие F1 от F2-reader.**
4. **`MemorySample`** с разбивкой self/children — F2-reader отдаёт одно число.
5. **`peak_mb`**, `degraded_source` флаг.

### Решение — не дублировать, а расширить
Два пути, выбрать и обосновать в PR:
- **A.** F1.`MemoryMonitor` внутри использует/наследует F2-шный
  `MemoryReader` для базового cgroup-чтения, добавляя опрос, историю,
  суммирование детей поверх. Меньше дублирования.
- **B.** F1 — самостоятельный, F2-reader остаётся для обратной
  совместимости, но `main` подаёт в каскад F1-монитор (он тоже
  удовлетворяет протоколу `MemoryReader`: `source` + `current_mb`).

**Рекомендация B:** F1 самостоятелен, но реализует протокол `MemoryReader`
из F2 (`source`, `current_mb`) — тогда `DegradationCascade(memory_reader=
memory_monitor)` работает без адаптера (критерий приёмки F1). F2-reader
остаётся как дефолт каскада, main подменяет его на F1 при старте.

### Критичное (из контракта, повтор ради важности)
- `current_mb()` НЕ делает I/O, НЕ бросает — вызывается из тика каскада.
- vmrss-режим суммирует детей, иначе память занижена на 550-700 МБ whisper.
- пороги из `[memory]` конфига, не хардкод.
- без `psutil` — `/proc` штатно.

## I3 — `app/drafts/trigger.py` [Middle]

Контракт `I3_drafts_trigger.md` — следовать. Критичные точки:

### Суть
`is_question(text, language) -> (bool, confidence)`. Правила, БЕЗ модели —
горячий путь, вызывается на каждый финальный сегмент собеседника.

### Что не забыть
1. **Только правила.** Ни LLM, ни ML. Вопросительный знак, вопросительные
   слова по языку (кто/что/сколько/когда/как для ru; qué/cómo/cuándo для
   es; what/how/when для en), вопросительная интонация-маркеры.
2. **Смещение в сторону срабатывания.** Порог 0.5 из конфига, но при
   сомнении — `True`. Лишний черновик игнорируется, пропущенный вопрос
   теряет функцию продукта (контракт).
3. **Языки из констант модуля** — ru/en/es/uk/pl. Списки вопросительных
   слов per-язык.
4. **Чистая функция**, без состояния, без БД, без сети.
5. **Не запускать на исходящем потоке** (микрофон пользователя) — вопросы
   детектируются только у собеседника. Но это решает вызывающий (main),
   не сам trigger — trigger просто отвечает на текст.

### Ловушка
Вопросительное слово в середине утверждения («я не знаю, как это») — не
вопрос. Простая эвристика «есть слово-вопрос → True» даст много ложных.
Учитывать позицию (начало фразы) и `?`. Но помнить правило смещения: при
сомнении лучше `True`.

## C3 — `app/audio/normalizer.py` [Middle]

Контракт `C3_normalizer.md` — следовать. **Блокер: решение владельца №1**
(отклонение §7). Контракт написан под «FFmpeg резервный, C3 — fallback
без FFmpeg».

### Уточнение владельца (из диалога)
Владелец уточнил цепочку:
1. `pw-record` с нужными параметрами (основной);
2. FFmpeg, настроенный сразу на 16k/mono/s16le (первый fallback);
3. `normalizer.py` — когда **FFmpeg упал/недоступен** (второй fallback).

Значит C3 — НЕ обёртка FFmpeg, а **альтернатива** ему: нормализация
средствами Python/stdlib, когда FFmpeg недоступен. Иначе «FFmpeg упал →
зовём FFmpeg из C3» бессмысленно.

### Что делает C3 по уточнению
- `needs_normalization(fmt) -> bool` — нужна ли конверсия;
- `normalize(pcm, src_fmt) -> bytes` — привести к 16k/mono/s16le
  **без внешнего процесса**: ресемплинг и свёртка каналов средствами
  Python (`audioop` из stdlib — `audioop.ratecv` для ресемплинга,
  `audioop.tomono` для свёртки стерео).
- быстрый путь: формат уже целевой → вернуть как есть, без работы.

### Тесты (владелец назвал явно)
1. **C3 включается, когда FFmpeg упал** — подменить FFmpeg-путь на
   падающий, убедиться, что управление переходит к C3.
2. **Эквивалентность FFmpeg vs C3** — на одном входе оба дают 16k/mono/
   s16le; качество (whisper-транскрипт совпадает на эталоне) — LIVE-тест.

### Ловушка
`audioop` устарел в Python 3.13 (deprecated), удалён в 3.13+. Проверить
версию Python проекта. Если 3.13+ — `audioop` недоступен, нужен
`audioop-lts` (бэкпорт) или ручной ресемплинг. **Зафиксировать в PR,
какой Python и какой путь ресемплинга** — это может стать зависимостью.

## UI-вкладки [Middle] — после E1 routes

Контракты готовы: E6 topbar, E7 settings, E5 diagnostics, E4 drafts,
E8 history. Все следуют одному инварианту (повтор — критичен):

**Вкладка не ведёт своего состояния сегментов. Подписка через
`stream.subscribe`, чтение `stream.getState()`, отрисовка дельты.
Логика — в E2 (`stream.js`).** Образец — `tab_translation.js` (E3, готов).

### Порядок и предусловия
| Вкладка | Ждёт | Приоритет для живого теста |
| :-- | :-- | :-- |
| topbar (E6) | routes /api/privacy | **Высокий** — §21.7 |
| settings (E7) | routes /api/key (G2 готов!), /api/library (I1 готов!) | **Высокий** — ключ, библиотека |
| diagnostics (E5) | routes /api/snapshot | Средний |
| drafts (E4) | I2 (после DRAFT-патча), G3 (готов) | Низкий — второй прогон |
| history (E8) | routes /api/export (G4 готов) | Низкий |

**Хорошая новость:** G2 (ключи) и I1 (библиотека) — оба реализованы.
Значит settings-вкладка не заблокирована по модулям, только по routes E1.

### Что не забыть (общее для всех)
- ключ в settings — `password`, после отправки очистить, показать маску,
  не в DOM/console/JS-state (G2 даёт маску);
- профиль в topbar — по событию `privacy.changed`, не по ответу POST;
- diagnostics только отображает snapshot, ничего не вычисляет;
- drafts — нет автокопирования, `has_gaps` виден;
- history — экспорт серверный, клиент не собирает форматы сам.
