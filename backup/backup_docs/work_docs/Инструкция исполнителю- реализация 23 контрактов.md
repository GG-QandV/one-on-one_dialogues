## Инструкция исполнителю: реализация 23 контрактов

### 1. Правила, действующие всегда

| Правило         | Формулировка                                                                                                           |
| --------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Источник правды | Контракт `CONTRACTS/*.md` → `INTERFACES.md` → `SPEC_speech_local_v2.md`. При расхождении кода и контракта правится код |
| Сигнатуры       | Из контракта дословно. Изменение сигнатуры — не правка кода, а вопрос к архитектору                                    |
| Импорты         | Только абсолютные: `from app.audio.pcm import Frame`                                                                   |
| Асинхронность   | Всё с вводом-выводом — `async`. Блокирующее — в `run_in_executor`                                                      |
| Исключения      | Только из `app/errors.py`. Новые — наследники `SpeechLocalError`                                                       |
| Датаклассы      | Пересекающие границу модулей — `frozen=True, slots=True`                                                               |
| Время           | В конвейере — мс от старта потока (`int`). В БД — ISO-8601 UTC (`str`)                                                 |
| Секреты         | Ключ не попадает в поля объектов, логи, исключения, `repr`                                                             |
| Ретраи          | Внутри модулей нет. Повторы — только `JobQueue`                                                                        |
| Логи            | Текст сегментов, черновиков и библиотеки — не выше DEBUG                                                               |

Раздел «Запрещено» в контракте — не рекомендация. Каждый пункт написан по конкретной ошибке, которая ломает инвариант спеки.

### 2. Порядок работы над одним файлом

1. Прочитать контракт целиком, включая «Подсказки» — там ловушки, экономящие итерацию.
2. Прочитать пункты спеки, указанные в шапке.
3. Написать тесты из «Критериев приёмки» — **до кода**. Каждый чекбокс = минимум один тест.
4. Написать код.
5. Прогнать тесты + `ruff` + `mypy --strict`.
6. Самопроверка: пройти по разделу «Запрещено» построчно.
7. PR с заголовком `[ID] модуль` и списком: какие чекбоксы закрыты, какие нет и почему.

Тест, которого нет в критериях приёмки, добавлять можно. Критерий, для которого нет теста, — блокирует PR.

```
Волна 1 (ничего не ждёт):   B1  B3  C6  C8  D1  D4  G1  I3
```

Жёсткие правила порядка:

* **G1 полностью принят до начала G2.** Иначе первый живой тест запишет ключ в лог.
* **D1 и D4 до D2/D3.** Провайдеры без базового класса и промптов не пишутся.
* **B3 до всего, что читает строки БД.** Литералы `'accurate'`, `'pending'`, `'copied'` после B3 запрещены — только перечисления.

### 5. Восемь ошибок, из-за которых PR возвращается

1. **Изменён `raw_text`** — капитализация, пунктуация, склейка. Поле неизменяемо (§8.1), это источник аудита.
2. **Тексты промптов переписаны «лучше»** — §11 и §12 предмет приёмки, копируются дословно.
3. **Ретрай внутри модуля** — ломает учёт попыток `JobQueue` и удваивает счёт за облако.
4. **Ключ в поле объекта или в `repr`** — берётся из `key_provider` в момент вызова.
5. **Результат быстрого трека попал в `raw_text` или в экспорт** — инвариант §8.3.
6. **Пропущен `privacy.validate` после сетевого вызова** — результат под старым поколением уйдёт в БД после переключения профиля.
7. **Хардкод порогов** — 800 мс, 1750 МБ, 4/3/2, 30000 токенов берутся из конфига.
8. **Прямая запись в `draft_answers`** — только `DraftGuard.store`.

### 6. Как проверять себя канареечным ключом

Везде, где модуль касается провайдера, в тестах используется `sk-CANARY-12345`. Проверка одна и та же:

python

```python
assert "sk-CANARY" not in repr(obj)
assert "sk-CANARY" not in str(exc)
assert "sk-CANARY" not in traceback.format_exc()
```

Для G1, G2 и H6 добавляется грep по файлам: лог, `*.db`, `*.db-wal`, `*.db-shm`, temp, экспорт.

### 7. Когда останавливаться и спрашивать

* Контракт противоречит спеке или другому контракту.
* Требуемое поведение недостижимо без изменения сигнатуры.
* Критерий приёмки невозможно проверить тестом.
* Внутри задачи обнаружился второй модуль (признак: файл уходит за полторы нормы LOC).

Во всех четырёх случаях — вопрос архитектору, а не собственное решение. Молча расширенная сигнатура ломает три модуля, которые её ждут.
