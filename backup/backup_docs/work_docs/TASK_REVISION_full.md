# Ревизия проекта speech-local: приведение к спеке без долгов и хвостов

Документ для агента-ревизора (Senior). Задача — довести репозиторий до
состояния, где нет пустышек-обманок, имена совпадают с контрактами,
инфраструктура собирается, а каждый готовый модуль сверен со спекой на
дрейф. Работа делится на две части: **Часть I — гигиена и порядок
реализации** (что доделать и в каком порядке), **Часть II — аудит дрейфа**
(сверка уже написанного кода со спекой).

Правило всего документа: **сначала исследовать, потом менять.** Дерево и
размеры файлов — ориентир, а не истина; перед каждой правкой открывать
файл и проверять факт.

# ЧАСТЬ II. Аудит дрейфа готовых модулей

Модуль может быть «написан и с зелёными тестами», но разойтись со спекой —
если тесты проверяют не тот инвариант. Эта часть — сверка уже
реализованного кода со спекой и `INTERFACES.md`. Для каждого модуля дан
**конкретный инвариант**, который надо подтвердить чтением кода, а не
запуском тестов.

Аудит не переписывает код без нужды. Результат каждого пункта: `ok` /
`дефект + строка + пункт спеки`. Найденный дрейф оформляется отдельной
задачей, не правится молча в ходе аудита.

## 5. Критические инварианты — проверить в первую очередь

Это инварианты, нарушение которых не ловится обычными тестами, но ломает
приёмку §21.

| ---:|:-------------------- |:------------------------------------------------------------------------------ |:----------------------------------------------------------------------------- |:------------------- |

# Что НЕ делать во всей ревизии

- Не переписывать готовый работающий код ради стиля — только по
  подтверждённому дрейфу от спеки.
- Не менять сигнатуры в `INTERFACES.md` без сверки всех зависимых
  модулей.
- Не заполнять пустые контракты на готовые модули — их удаляют (§1.4).
- Не выдумывать поля и поведение, которых нет в спеке, чтобы «закрыть»
  пункт — фиксировать как gap.
- Не считать модуль проверенным по факту зелёных тестов: тесты могут
  проверять не тот инвариант (см. §5).
- Не смешивать аудит и исправление в одном проходе.
