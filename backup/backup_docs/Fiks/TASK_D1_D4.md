# Задание мидл-агенту: D1 + D4 (связка)

| | |
| :-- | :-- |
| Файлы | `app/translation/base.py`, `app/translation/prompts.py` |
| Контракты | `CONTRACTS/D1_provider_base.md`, `CONTRACTS/D4_prompts.md` |
| Объём | 215 + 245 LOC, 11 + 19 тестов |
| Блокирует | D2, D3, D6, I4 — четыре задачи стоят на этой паре |
| Фикстуры | `tests/fixtures/prompts_spec_11.json`, `tests/fixtures/drift_20.json` (выданы вместе с заданием) |

## Почему это одна задача, а не две

Между модулями циклическая связь: `prompts` импортирует типы из `base`,
а `base` вызывает `prompts.audit` внутри финального `translate`. Разные
агенты, работающие параллельно, разрешат цикл по-разному, и сборка
развалится на первом импорте.

Разрыв цикла зафиксирован контрактом: **`base` не импортирует `prompts`
на уровне модуля**. Либо `auditor` передаётся в конструктор фабрикой,
либо `translate` делает отложенный импорт внутри метода. Это единственное
допустимое отступление от правила абсолютных импортов верхнего уровня.

## Порядок работ: три шага, шаг 3 обязателен

### Шаг 1 — `base.py` без аудита

Реализовать целиком: типы, протокол приватности, работу с ключом,
таймаут, `_classify`, валидацию результата. Параметр `auditor` в
конструкторе присутствует, по умолчанию `None`, при `None` аудит
пропускается.

Закрываются 8 чекбоксов из 11:

```
[ ] translate в конфиденциальном профиле проходит
[ ] translate после switch() посреди вызова → StaleGenerationError
[ ] Пустой ключ → ProviderAuthError, сетевого вызова не было
[ ] Таймаут → ProviderUnavailable, в сообщении нет текста запроса
[ ] Коды 401/429/503/400 → правильные типы и retryable
[ ] Пустой ответ при непустом входе → ProviderResponseInvalid
[ ] LIVE_LITERAL без потерь → translation_clean is None, changes == ()
[ ] Ключ не встречается в repr() и в тексте любого исключения
```

### Шаг 2 — `prompts.py` целиком

`build`, `format_context`, `validate_response`, `filler_changes`,
`detect_drift`, `audit`, `AuditConfig`, `LANGUAGE_NAMES`, `FILLERS`.

Закрываются все 19 чекбоксов D4.

### Шаг 3 — возврат в `base.py`

Подключить `auditor` по умолчанию через отложенный импорт. Закрываются
три оставшихся чекбокса:

```
[ ] auditor вызывается ровно один раз за translate, после privacy.validate
[ ] Перевод с пропавшим числом → в changes элемент lost_entity,
    исключения нет, translation_raw не изменён
[ ] auditor is None → отложенный импорт prompts.audit отрабатывает,
    цикла импортов нет (тест импортирует app.translation.base первым)
```

**Шаг 3 нельзя отложить.** `base.py` с молча пропускаемым аудитом
выглядит рабочим, проходит 8 тестов из 11 и уходит в D2/D3 как готовый.
Обнаружится это на приёмке H2, когда числа начнут теряться без единой
пометки.

## Пять мест, где эта пара ломается чаще всего

### 1. `str.format` на промпте `post_clean`

Текст §11.3 заканчивается строкой:

```
Верни JSON: {"clean_text": "...", "changes": [...]}
```

`str.format` на этой строке падает с `KeyError: '"clean_text"'`.
Подстановка языков — только через `str.replace` по именам
плейсхолдеров, ни `format`, ни f-строки.

### 2. Фикстура промптов, сгенерированная из кода

`tests/fixtures/prompts_spec_11.json` скопирован из спеки вручную и
выдан вместе с заданием. Пересобирать его из `prompts.py` нельзя: тест
превратится в сравнение модуля с самим собой и будет зелёным при любой
правке текста промпта.

### 3. Поиск филлеров по подстроке

`FILLERS` содержит `"мм"`. Поиск по подстроке даёт срабатывание на
словах «суммы», «коммерческий», «программа» — и `changes` заполняется
мусором на каждом сегменте. Только границы слов, регистронезависимо.

### 4. Аудит как исключение

`audit` и `detect_drift` **не бросают ничего и никогда**. Подозрение на
дрейф — пометка в `changes`, а не отказ перевода. Сегмент с потерянным
числом всё равно сохраняется: решение принимает человек, а не модуль.

### 5. Ложные срабатывания дрейфа

В `drift_20.json` половина случаев — негативные: перестановка чисел,
`30 000` против `30,000`, `7,5` против `7.5`, транслитерация имени,
короткая реплика «Да». Каждое ложное срабатывание на них — такой же
провал, как пропуск потерянного числа. Лог, который сыпет ложняками,
перестают читать через день.

## Открытые решения, уже принятые владельцем

| Вопрос | Решение |
| :-- | :-- |
| `changes` для `LIVE_SAFE` при недоказанном удалении | Фиксировать всё равно. Запись означает «предъявлено к удалению», не «удалено» |
| Проверка имён и названий | Выключена по умолчанию (`check_names=False`) — транслитерация даёт ложняки |
| Отдельный статус `drift_suspect` в БД | Отложено. Дрейф виден только в `changes` / `edit_log_json` |

Ничего из этого не пересматривать в ходе реализации.

## Если что-то не сходится

Останавливаться и спрашивать, а не решать самому:

- контракт противоречит спеке §11 или другому контракту;
- требуемое поведение недостижимо без изменения сигнатуры;
- критерий приёмки непонятно как проверить тестом;
- файл вырос больше чем в полтора раза от оценки LOC.

Молча расширенная сигнатура ломает четыре модуля, которые её ждут.
