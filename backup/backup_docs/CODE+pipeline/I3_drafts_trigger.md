# I3 — триггер: определение вопроса клиента

| | |
| :-- | :-- |

| Уровень | Middle |
| Оценка | 160 LOC, 10 тестов |
| Зависит от | `app/stt/parser.py` (C6, типы), `app/errors.py` (готов) |
| Блокирует | I2 (запуск генератора), вкладка «Черновики» (E) |
| Пункт спеки | §12 «Триггер» |

## Задача

Решить по тексту сегмента, задан ли вопрос, требующий черновика ответа.
Спека §12: генерация запускается **автоматически на каждый вопрос клиента
во входящем потоке** — то есть решение принимается без участия
пользователя, десятки раз за встречу.

Цена ошибок несимметрична и задаёт весь дизайн модуля:

| Ошибка | Цена |
| :-- | :-- |
| Ложное срабатывание | Лишний черновик во вкладке, пользователь его игнорирует. Плюс один запрос к провайдеру |
| Пропуск вопроса | Функция не сработала в тот момент, ради которого её делали |

Поэтому порог смещён в сторону срабатывания, а не точности. Верхнего
контура здесь нет: `DraftGuard` (I5) проверяет содержимое черновика, но
не проверяет, был ли вопрос.

## Интерфейс

```python
@dataclass(frozen=True, slots=True)
class TriggerConfig:
    threshold: float = 0.5          # решение True при confidence >= threshold
    min_words: int = 3              # короче — только по знаку вопроса
    max_words: int = 60             # длиннее — почти наверняка монолог

def is_question(text: str, language: str) -> tuple[bool, float]:
    """-> (решение, уверенность 0..1)"""

def score(text: str, language: str) -> float:
    """Только уверенность, без решения. Для отладочного экрана E6."""

QUESTION_WORDS: dict[str, frozenset[str]]
AUX_VERBS: dict[str, frozenset[str]]
```

## Поведение

1. **Правила, а не модель.** Никаких вызовов LLM, никаких ONNX-моделей,
   никакой загрузки словарей с диска. Модуль работает на каждом сегменте
   входящего потока в горячем пути; запрос к облаку ради решения «звонить
   ли в облако» удваивает стоимость и задержку функции.

2. **Сигналы и веса.** Уверенность — максимум из сработавших сигналов,
   а не сумма (сумма даёт 1.0 на любой длинной фразе с двумя признаками):

   | Сигнал | Вес |
   | :-- | --: |
   | Текст оканчивается на `?` | 0.95 |
   | `¿` в начале (ES) | 0.95 |
   | Вопросительное слово в первых двух токенах | 0.80 |
   | Вспомогательный глагол в начале (EN/DE-подобный порядок) | 0.70 |
   | Вопросительная частица (`ли`, `czy`, `чи`) | 0.75 |
   | Вопросительное слово в середине фразы | 0.45 |
   | Ничего из перечисленного | 0.0 |

3. **Языки.** Наборы слов — константы модуля для `en`, `es`, `ru`, `uk`,
   `pl` (языки распознавания по спеке §4). Неизвестный или пустой язык →
   работают только пунктуационные сигналы (`?`, `¿`), словарные — нет.

4. **Знак вопроса ненадёжен, но остаётся сильнейшим сигналом.** whisper
   расставляет пунктуацию сам и на коротких репликах её теряет. Поэтому
   отсутствие `?` вопрос не отменяет, а наличие — почти решает.

5. **Границы длины.** Меньше `min_words` слов: решение только по `?`,
   словарные сигналы не применяются («что» в реплике «что-то не так»).
   Больше `max_words`: уверенность умножается на 0.5 — длинная реплика с
   вопросительным словом посередине обычно рассказ, а не вопрос.

6. **Нормализация перед разбором.** `casefold`, схлопывание пробелов,
   обрезка краёв. Пунктуация внутри слова не удаляется. Текст сегмента
   (`raw_text`) не модифицируется — работа идёт с локальной копией.

7. **Составные реплики.** Если текст содержит `?` не в конце («Сколько
   стоит? Мы смотрели у конкурентов»), сигнал `?` засчитывается с весом
   0.85: вопрос был, но за ним идёт продолжение.

8. **Функция чистая.** Ни сети, ни БД, ни логирования побочными
   эффектами, ни состояния между вызовами. Дедупликация повторных
   срабатываний — не здесь: этим занимается вызывающий обработчик.

## Запрещено

- Вызывать LLM или любой сетевой сервис для классификации.
- Обращаться к БД и к истории сегментов: решение принимается по одному
  тексту.
- Накапливать состояние между вызовами (счётчики, кэши, «последний
  вопрос»): модуль обязан быть переиспользуем без сброса.
- Поднимать порог ради «чистоты» вкладки черновиков: несимметричность
  цены ошибок зафиксирована в §12.
- Применять словарные сигналы к тексту короче `min_words` слов.
- Запускать триггер на исходящем потоке (`role='microphone'`): черновик
  готовится на вопрос клиента, а не на ваш собственный. Фильтр по роли —
  на стороне вызывающего, но контракт это фиксирует.
- Бросать исключения: пустая строка — валидный вход, ответ
  `(False, 0.0)`.

## Критерии приёмки

- [ ] «Сколько это будет стоить?» / `ru` → `(True, 0.95)`
- [ ] «сколько это будет стоить» (без знака) / `ru` → `True`,
      уверенность ≥ 0.8
- [ ] «What is your delivery time» / `en` → `True`
- [ ] «Can you deliver by March» / `en` → `True` (вспомогательный глагол)
- [ ] «¿Cuánto cuesta» / `es` → `True`
- [ ] «Czy możemy zacząć w marcu» / `pl` → `True` (частица `czy`)
- [ ] «Мы можем начать в марте, если вы подтвердите условия» / `ru` →
      `False`
- [ ] «что-то не так» / `ru` (3 слова после нормализации — на границе) →
      `False`
- [ ] «Сколько стоит? Мы смотрели у конкурентов» → `True`,
      уверенность 0.85
- [ ] Неизвестный язык `xx` с текстом «сколько это стоит» → `False`;
      с «сколько это стоит?» → `True`
- [ ] Пустая строка и строка из пробелов → `(False, 0.0)`, без исключения
- [ ] Модуль не делает ввода-вывода (проверяется отсутствием импортов
      `asyncio`, `sqlite3`, `httpx`) и не хранит состояния (два вызова
      подряд с одним входом дают идентичный результат)

## Подсказки

Скелет словарей:

```python
QUESTION_WORDS = {
    "ru": frozenset({"кто", "что", "где", "когда", "почему", "зачем",
                     "сколько", "какой", "какая", "какие", "как", "чей"}),
    "en": frozenset({"who", "what", "where", "when", "why", "how",
                     "which", "whose", "whom"}),
    "es": frozenset({"quién", "qué", "dónde", "cuándo", "por", "cómo",
                     "cuánto", "cuál"}),
    "uk": frozenset({"хто", "що", "де", "коли", "чому", "скільки",
                     "який", "як", "чий"}),
    "pl": frozenset({"kto", "co", "gdzie", "kiedy", "dlaczego", "ile",
                     "jaki", "jak", "czyj"}),
}

AUX_VERBS = {
    "en": frozenset({"do", "does", "did", "is", "are", "was", "were",
                     "can", "could", "will", "would", "should", "have",
                     "has", "may", "might"}),
}

PARTICLES = {"ru": ("ли",), "uk": ("чи",), "pl": ("czy",)}
```

Ловушки:
- испанское «por qué» — два токена, а «porque» (потому что) — один и
  вопросом не является; проверять пару токенов, а не подстроку;
- английское «how» встречается в «how about» и «I know how it works» —
  спасает правило «в первых двух токенах»;
- русское «как» очень частотно в утверждениях («как договаривались») —
  вес 0.80 применяется только в начале фразы, в середине 0.45, и при
  пороге 0.5 срабатывания не даёт;
- эмодзи и служебные вставки whisper к моменту вызова уже удалены
  парсером C6 — повторно чистить не нужно;
- порог вынесен в `TriggerConfig` не ради красоты: после первой живой
  встречи его почти наверняка придётся двигать, и это не должно быть
  правкой кода.
