| | |

## Задача

Единственное место в проекте, где живут тексты промптов и правила разбора
ответа модели. Провайдеры (D2, D3, будущий custom HTTP) собирают запрос из
того, что вернул `build`, и разбирают ответ через `validate_response`.

Причина изоляции прямая: спека §11 фиксирует тексты дословно, а критерий
приёмки блока D — идентичность чисел, дат, имён и URL на эталонном наборе.
Если тексты промптов размножатся по провайдерам, эталонный набор перестанет
проверять модель и начнёт проверять копипасту.

## Интерфейс

```python
def build(mode: TranslationMode, req: TranslationRequest) -> tuple[str, str]:
    """-> (system_prompt, user_prompt). Тексты — из спеки §11 дословно."""

def format_context(context: tuple[str, ...]) -> str:
    """Блок контекста с пометкой «не переводить». Общий для всех провайдеров."""

def validate_response(mode: TranslationMode, raw: str) -> TranslationResult:
    """Разбор ответа. POST_CLEAN обязан вернуть строгий JSON."""

def filler_changes(req: TranslationRequest) -> tuple[Change, ...]:
    """Слова-паразиты, предъявленные к удалению. Только LIVE_SAFE."""

def detect_drift(req: TranslationRequest,
                 translation: str) -> tuple[Change, ...]:
    """Сущности, пропавшие из перевода. Все режимы."""

def audit(req: TranslationRequest,
          result: TranslationResult) -> TranslationResult:
    """filler_changes + detect_drift, дописывает changes. Вызывает D1."""

@dataclass(frozen=True, slots=True)
class AuditConfig:
    check_numbers: bool = True
    check_urls: bool = True
    check_length: bool = True
    check_names: bool = False       # эвристика, по умолчанию выключена
    length_ratio_min: float = 0.6

LANGUAGE_NAMES: dict[str, str]      # ISO 639-1 -> название для промпта
FILLERS: tuple[str, ...]            # список слов-паразитов из §11.2
```

**Направление зависимостей.** `prompts` импортирует типы из `base`;
`base` вызывает `prompts.audit` отложенным импортом. Обратный импорт на
уровне модуля запрещён — цикл.

## Поведение

1. **Тексты промптов — константы модуля, скопированные из спеки §11
   дословно**, включая пунктуацию и кавычки-ёлочки в списке слов-паразитов.
   Единственная допустимая правка — подстановка `{source_language}` и
   `{target_language}`. Переформулировка, «улучшение» и перевод промптов на
   английский запрещены: спека §11 — предмет приёмки, а не рекомендация.

2. **Разделение system/user.** В `system_prompt` уходит инструкция режима
   из §11. В `user_prompt` — блок контекста (если непустой) и переводимый
   текст. Причина: только так работает кэширование префикса у обоих
   провайдеров — инструкция режима неизменна в пределах сессии, текст
   меняется каждый сегмент.

3. **Подстановка языков.** Коды ISO 639-1 заменяются на **английские**
   названия из `LANGUAGE_NAMES` (`ru` → `Russian`, `uk` → `Ukrainian`).
   Обоснование: на коде `uk` модели периодически выдают ответ, спутав его с
   `en-UK`; полное название снимает неоднозначность. Неизвестный код
   подставляется как есть, без исключения.

4. **Блок контекста.** Формат фиксирован и одинаков у всех провайдеров:

   ```
   Контекст предыдущих реплик (НЕ переводить, только для понимания):
   1) …
   2) …

   Текст для перевода:
   …
   ```

   Пустой `req.context` → блок не добавляется вовсе, не добавляется и
   заголовок «Текст для перевода». Лишний служебный текст в запросе на
   коротких сегментах составляет заметную долю токенов.

5. **`validate_response`, live-режимы.** Обрезать края, снять обёртку
   ` ```…``` `, если она покрывает весь ответ. **Кавычки не трогать** —
   в переговорах кавычки бывают частью текста. Пустая строка →
   `ProviderResponseInvalid`. `translation_clean is None`.

6. **`validate_response`, `POST_CLEAN`.** Строгий JSON:
   `{"clean_text": str, "changes": [...]}`. Обязателен `clean_text`;
   `changes` отсутствует → пустой кортеж. Неизвестное значение `type` в
   элементе `changes` приводится к `"other"`, элемент не отбрасывается.
   Невалидный JSON, отсутствие `clean_text`, `clean_text` не строка →
   `ProviderResponseInvalid`. Распределение по полям результата — п. 7.

7. **Разграничение полей результата** (спека §10.1, инвариант БД 4):
   
   | Режим | `translation_raw` | `translation_clean` | `changes` |
   | :-- | :-- | :-- | :-- |
   | `LIVE_LITERAL` | перевод | `None` | только п. 9 |
   | `LIVE_SAFE` | перевод | `None` | п. 8 + п. 9 |
   | `POST_CLEAN` | исходный текст ответа модели | `clean_text` | из JSON + п. 9 |

8. **`filler_changes` — фиксация без проверки (решение владельца принято).**
   Промпт §11.2 возвращает только перевод, списка удалённого модель не
   даёт. По константе `FILLERS` ищутся вхождения в `req.text` (границы
   слов, регистронезависимо), каждое даёт
   `Change(type="filler_removed", original=<слово>, replacement="")`.
   Запись означает «предъявлено к удалению», а не «удалено»: проверить
   факт удаления нельзя, перевод на другом языке. Владелец подтвердил, что
   фиксация ведётся даже при недоказанном удалении — сами по себе филлеры
   смысла не несут, риск лежит в другом месте (п. 9).

9. **`detect_drift` — то, ради чего аудит существует.** Опасен не
   неудалённый филлер, а вычищенное «под филлер» отрицание, предлог,
   окончание или число: перевод остаётся гладким, а смысл смещается.
   Сравниваются языконезависимые сущности оригинала и перевода:

   | Проверка | Механизм | Порог срабатывания |
   | :-- | :-- | :-- |
   | Числа, суммы, даты | `extract_numbers` из `drafts/guardrails.py` (готов): «30 000» = «30000€» = «30к» | множество перевода не покрывает множество оригинала |
   | URL, email, артикулы | регулярка, сравнение множеств после `casefold` | любая пропажа |
   | Обвал длины | слов в переводе / слов в оригинале | `< length_ratio_min` (0.6) |
   | Имена, названия | токены с заглавной не в начале фразы | выключено по умолчанию: транслитерация даёт ложные срабатывания |

   Каждая пропажа → `Change(type="lost_entity", original=<что пропало>,
   replacement="")`. Числа сравниваются как множества значений, не позиций:
   перестановка в предложении дрейфом не считается.

10. **`audit` ничего не отменяет.** Возвращает результат с дописанным
    `changes`, исключений не бросает, `translation_raw` не трогает.
    Подозрение на дрейф — сигнал человеку в `edit_log_json` и в UI, а не
    отказ сегмента. **Отложенное решение владельца:** заводить ли
    отдельный `translation_status='drift_suspect'` (требует миграции БД) —
    до решения дрейф виден только в `changes`.

11. **Все функции модуля чистые.** Ни сети, ни БД, ни логирования побочными
    эффектами. `provider_request_id` здесь неизвестен: провайдер
    дозаполняет его через `dataclasses.replace` после разбора.

## Запрещено

- Менять тексты промптов относительно спеки §11 — включая перестановку
  строк и замену кавычек.
- Добавлять в промпт что-либо не предусмотренное §11: «think step by step»,
  указание формата вывода сверх §11.3, роль-персону, примеры.
- Хардкодить имена провайдеров и подстраивать текст под конкретную модель.
- Разбирать JSON `POST_CLEAN` регулярными выражениями.
- Молча возвращать `translation_clean` для live-режимов.
- Пытаться «починить» отказ модели переводить — это ответственность
  провайдера (D3 п. 10).
- Бросать исключение из `audit` или `detect_drift`.
- Восстанавливать «потерянное» число в тексте перевода: `translation_raw`
  приходит от модели и правится только человеком в редакторе.
- Включать проверку имён по умолчанию: транслитерация («Иванов» →
  «Ivanov», «Ivanoff») даёт ложные срабатывания на каждом сегменте, а лог,
  который сыпет ложняками, перестают читать.
- Логировать `req.text` и `raw` на уровне INFO и выше.

## Критерии приёмки

- [ ] Тексты трёх промптов побайтово совпадают со спекой §11 после
      подстановки языков (тест сравнивает с фикстурой, скопированной
      из спеки, а не с литералом из того же модуля)
- [ ] `build(LIVE_LITERAL, req)` c `source="ru", target="en"` → в system
      присутствуют `Russian` и `English`, кодов `ru`/`en` нет
- [ ] Неизвестный код языка (`xx`) подставляется как есть, без исключения
- [ ] Пустой `context` → в `user_prompt` нет ни заголовка контекста,
      ни заголовка «Текст для перевода»
- [ ] Контекст из 3 элементов пронумерован и помечен «НЕ переводить»
- [ ] `validate_response(LIVE_LITERAL, "  перевод  ")` → обрезано,
      `translation_clean is None`, `changes == ()`
- [ ] Ответ, целиком обёрнутый в ` ```…``` `, разворачивается; кавычки
      внутри текста сохраняются
- [ ] `validate_response(LIVE_LITERAL, "")` → `ProviderResponseInvalid`
- [ ] `POST_CLEAN` с валидным JSON → `translation_clean` заполнен,
      `changes` разобран, неизвестный `type` приведён к `"other"`
- [ ] `POST_CLEAN` без `clean_text` → `ProviderResponseInvalid`
- [ ] `POST_CLEAN` с невалидным JSON → `ProviderResponseInvalid`
- [ ] `LIVE_SAFE`: вход «ээ, нам нужно эм проверить договор» → в `changes`
      два элемента `filler_removed`
- [ ] «суммы», «коммерческий» не дают ложных `filler_removed` (границы слов)
- [ ] Оригинал «сумма 30 000 евро до 15 марта» → перевод без «30 000»:
      один `lost_entity` с `original="30000"`
- [ ] Перестановка чисел в переводе дрейфом не считается
- [ ] Пропавший URL → `lost_entity`; совпадающий URL — нет
- [ ] Оригинал 40 слов → перевод 20 слов: `lost_entity` по длине;
      перевод 30 слов — нет
- [ ] `check_names=False` по умолчанию: «Иванов» → «Ivanov» не даёт
      срабатывания
- [ ] `audit` не бросает исключений ни на одном входе из набора
      `tests/fixtures/drift_20.json` и не меняет `translation_raw`
- [ ] Функция не делает ввода-вывода (проверяется отсутствием импортов
      `asyncio`, `sqlite3`, `httpx`)

## Подсказки

Скелет констант:

```python
_LIVE_LITERAL_SYSTEM = (
    "Переведи текст с {source_language} на {target_language}.\n"
    "Не добавляй и не удаляй факты.\n"
    "Сохрани числа, суммы, валюты, даты, имена, названия компаний,\n"
    "артикулы, номера, ссылки и единицы измерения без изменений.\n"
    "Не объясняй перевод. Верни только перевод."
)

FILLERS = ("ээ", "эээ", "эм", "эмм", "мм", "ммм", "uh", "um", "er")

LANGUAGE_NAMES = {"ru": "Russian", "en": "English", "es": "Spanish",
                  "uk": "Ukrainian", "pl": "Polish", "de": "German",
                  "fr": "French", "pt": "Portuguese", "it": "Italian"}
```

Тест «промпт не разъехался со спекой» стоит написать так: фикстура
`tests/fixtures/prompts_spec_11.json` создаётся копированием из
`SPEC_speech_local_v2.md` вручную один раз; тест сравнивает её с выводом
`build`. Сравнение модуля с самим собой ничего не проверяет.

Ловушки:
- слова-паразиты в §11.2 записаны в кавычках-ёлочках — при поиске
  вхождений в `req.text` кавычки не участвуют, ищутся сами слова;
- `mm`/`мм` встречается внутри слов («суммы») — искать по границам слова,
  иначе `changes` заполнится мусором на каждом сегменте;
- у `LIVE_SAFE` и `LIVE_LITERAL` разный system, но одинаковый user —
  собирать user одной общей функцией.
